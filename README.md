# 안성제철 — 처음 오신 팀원은 여기부터

두 조종사가 65m 거대 로봇의 팔을 하나씩 맡아 보스 한 기를 쓰러뜨리는 협동 VR 게임입니다. 5인 캡스톤, **중간발표 10/30, 전시 12/11**.

이 파일 하나만 끝까지 읽으면 무엇을 받고, 어디를 보고, 어떻게 묻고, AI를 어떻게 쓰는지 알 수 있습니다. 15분이면 됩니다.

---

## 1. 레포 받기 (처음 한 번)

> 지시서를 **읽기만** 할 거면 받지 않아도 됩니다. 휴대폰이나 PC 브라우저에서 이 레포 → `docs` → `members` → 자기 이름 파일을 열면 됩니다.
> Unity로 작업하거나 파일을 직접 올릴 사람(성재·윤주, 필요하면 유진)은 아래대로 받습니다.

1. GitHub 초대 메일을 **수락**합니다. (메일이 없으면 팀 단톡방에 GitHub 아이디를 올려 주세요.)
2. **GitHub Desktop**을 설치하고 로그인합니다.
3. File → Clone repository → URL 탭에 `https://github.com/Lunatic2339/anseong-steel-v2.git`
4. 저장 위치는 **경로에 한글이 없는 곳**으로 합니다(예: `C:\Projects\`). 한글 경로는 Unity에서 문제가 생깁니다.
5. Unity가 필요하면 Unity Hub → Projects → Add → Add project from disk → 받은 폴더. 버전은 **6000.3.26f1** 정확히 이것만(자세한 설치는 자기 지시서에 있음). "버전이 다르다"는 창이 뜨면 **업그레이드하지 말고 취소**합니다.

## 3. 매번 작업 시작할 때

1. **최신 받기**: GitHub Desktop 위쪽 **Fetch origin** → **Pull origin**. (브라우저로만 보는 사람은 할 것 없음)
2. 자기 파일 맨 위 **"마지막 수정"** 날짜와 **"바뀐 기록"**을 봅니다. 바뀌었으면 "지금 할 일"과 "다른 작업에서 온 요청"을 다시 확인합니다.
3. 요청을 시작하면 팀 단톡방에 "○○ 요청 시작해요", 끝나면 "끝났어요" 한 줄. (파일의 상태 칸은 Claude나 코드 담당이 바꿉니다. 직접 바꿔도 됩니다.)

## 5. 모두 꼭 지킬 것

- **Unity 코드는 코드 담당(선우)과 Claude만 씁니다.** 나머지는 아트·소리·하드웨어·기획·발표 결과물(파일, 프리팹, 표)을 넘깁니다.
- `Scenes/Main.unity`는 코드 담당(선우)만 수정합니다. 씬 작업은 `Scenes/Sandbox/Sandbox_<이름>.unity`에서 하고 프리팹으로 넘깁니다.
- **프로젝트 설정·패키지는 바꾸지 않습니다.** AI가 바꾸라고 해도 하지 않고 팀 단톡방에 먼저 물어봅니다.
- 모델 뼈대(뼈 이름·개수), 팔 길이 비율, 단위(m)·정면(+Z)은 바꾸지 않습니다. 바꾸면 코드가 깨집니다.
- 밖에서 받은 모델·텍스처·소리, **AI로 만든 파일도** 출처를 적습니다: `파일 이름 / 사이트(또는 AI 서비스) / 제목 / 만든 사람 / 라이선스(이용 조건) / 주소`. 같은 폴더의 `SOURCES.md`나 드라이브 `SOURCES`에. 전시 작품이라 출처를 모르는 파일은 쓰지 않습니다.
- 파일 하나 50MB 이하. 중간 저장본은 드라이브에, 확인된 버전만 레포에.
- 공개 레포입니다. **비밀번호·계정 정보는 절대 레포에 쓰지 않습니다.**
- 마감 구조: 결과물은 마감 **하루 전**까지(예: 중간발표용은 10/28). 11/19 기능 동결, 11/26 아트 동결, 12/7 코드 동결.

## 6. 막혔을 때, 수정 요청할 때

파일 위치나 연결이 헷갈리면 먼저 [`docs/폴더_지도.md`](docs/폴더_지도.md)를 봅니다. 그래도 모르겠으면 혼자 30분 넘게 붙잡지 말고 **팀 단톡방**에 이 양식으로 올립니다.

```
[문제] 이름 / 지시서 번호(예: A-02 1단계)
무엇을 하다가: 
무슨 일이 생겼나: 
화면 캡처: (첨부)
```

- 지시서가 틀린 것 같거나 바꾸고 싶은 점(마감, 순서, 방법)도 같은 양식에 `[수정 요청]`으로 올리면 됩니다.
- 올린 글은 코드 담당(선우)이 총괄 채팅(Claude)에 넘기고, Claude가 지시서 파일을 고칩니다. 고쳐지면 팀 단톡방에 "내 파일 확인해 주세요"라고 알려 드립니다.
- GitHub에 익숙하면 자기 파일에서 연필(✏️) 버튼으로 직접 고쳐도 됩니다. 그래도 단톡방에 한 줄 알려 주세요.
- 결정이 필요한 것(돈, 방향, 고르기)은 **팀 회의에서 정할 것**으로 올립니다.
- 작업하다 생긴 질문이나 "내 판단으로 이렇게 바꿨다"는 내 폴더 `작업_노트.md`에 적고 파일과 같이 커밋하면 Claude가 답합니다(코드 담당 확인 후 올라옴). 순서: [작업 노트](docs/members/README.md#작업-노트-질문변경을-claude에게-묻기).

## 7. 결과물 넘기기 (둘 중 편한 쪽)

**가. 드라이브 + 단톡방** (가장 쉬움)
지시서에 적힌 드라이브 폴더에 올리고 팀 단톡방에 링크. 코드 담당(선우)의 Claude가 레포에 넣습니다.

**나. 직접 레포에 올리기**
순서와 브랜치 이름은 [`docs/GitHub_작업_규칙.md`](docs/GitHub_작업_규칙.md)에 있습니다. 핵심은 세 줄입니다.
1. 내 이름 브랜치(`yujin`, `sungjae`, `yunju`, `gogeon`) 하나만 계속 쓴다. `main`·`develop`에는 직접 올리지 않는다.
2. 내 브랜치에 커밋·푸시까지만 한다. PR도 병합도 하지 않는다.
3. 팀 단톡방에 `[올림]` 양식으로 알린다. 코드 담당(선우)이 중간중간 브랜치를 확인해 필요한 파일만 `develop`(작업 기준 브랜치)으로 가져간다.

Claude Code를 쓰는 사람은 "지금까지 커밋하고 푸시해줘" 한 마디로 대신할 수 있습니다([AI 사용법](docs/AI_사용법.md)).

## 8. AI 쓰는 법 (Claude / ChatGPT)

AI는 반복 작업·스크립트·표 정리·초안에 강하고, 눈으로 보고 다듬는 일과 최종 판단은 약합니다. 쓰는 법(Claude Code 첫 마디, ChatGPT에 붙여 넣을 시작 문구, 공통 주의)은 **[`docs/AI_사용법.md`](docs/AI_사용법.md)**, 내 일에서 무엇을 맡길지는 내 폴더의 `AI_활용.md`에 있습니다.
