`CLAUDE.md`와 `docs/design/`의 내용(65m 로봇, 두 사람이 팔 하나씩, 맨손 보스전)은 **예전 기획**입니다. 이 브랜치에서는 이 문서가 먼저입니다. 코드 규칙과 Unity 작업 규칙은 `CLAUDE.md` 것을 그대로 따릅니다.

## 5. 돌려 보기

- Unity 6000.3.26f1로 연다. 메뉴 `Anseong → Sandbox → Build Boss Act 1`을 누르면 장면이 새로 만들어져 `Scenes/Sandbox/Sandbox_BossAct1.unity`에 저장된다. **저장된 장면을 그냥 열지 말고 메뉴로 다시 만든다**(모델 파일이 없는 PC에서는 연결이 끊겨 있다).
- Play 뒤 시작 화면에서 1(혼자), 2(호스트 = P1), 3(접속 = P2).
- 키보드와 마우스(헤드셋 없이): 마우스로 보기, 왼쪽 버튼 = 쏘기/베기, 오른쪽 버튼 = P1 막기 또는 P2 스캔 버튼, Q/E = 왼쪽/오른쪽 막기, A/D = 옆으로 한 걸음, 왼쪽 Ctrl = P2 숨기, C = 취소. 운영자 키: R 다시 시작, Enter P2 없이 시작, B 빈 자리 자동 조작, G 혼자일 때 자리 바꾸기.
- 헤드셋: 왼손 트리거 = P1 막기(왼손이 얼굴 가운데보다 왼쪽이면 왼쪽, 오른쪽이면 오른쪽) 또는 P2 스캔 버튼, 오른손 트리거 = P2 쏘기 또는 P1 베기(쥔 채 손을 앞으로 빠르게), 왼손 스틱을 옆으로 = 옆으로 한 걸음.
- 테스트: `Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults Logs/editmode-results.xml -logFile Logs/editmode.log`. 지금 466개 가운데 464개 통과이고, 실패 2개는 예전 기획의 `DefenseTests`입니다(이 판과 무관, 원인 미확인).
- 두 PC용 실행 파일: `Unity.exe -batchmode -projectPath . -executeMethod Anseong.EditorTools.SkirmishSandboxMenu.BuildBossAct1Player -quit`로 `Builds/BossAct1/AnseongBossAct1.exe`를 만든다. `AnseongBossAct1.exe -mode host`와 `-mode client [-ip 호스트주소]`. 한 PC에서 둘을 같이 띄워 접속만 볼 때는 `-ip 127.0.0.1`. 11/27에 한 PC에서 양쪽이 맞는 것까지 봤고(1막만 있던 때), 실제 두 PC로는 아직입니다.

## 7. 코드를 고치게 될 때의 규칙

- 자기 브랜치를 `feat/next-z2-gunship`에서 따고(성재: `sungjae`), 푸시한 뒤 선우에게 알린다. `develop`과 `main`은 건드리지 않는다. 합치는 것은 선우가 한다.
- 규칙은 `SkirmishSession`과 `GruntDuel`에만 둔다. 화면 코드에 규칙을 넣지 않는다. 규칙을 고치면 `BossActTests`에 테스트를 붙이고 전체 테스트를 돌린다.
- `SkirmishSession.cs`, `SkirmishTypes.cs`, `SkirmishNet.cs`, `SkirmishSettings.cs`, `GruntDuel.cs`는 선우 쪽이 거의 매일 고치는 파일입니다. 여기를 고칠 때는 미리 알리고, 한 번에 작게 고친다.
- `.unity`, `.prefab`, `.meta`를 손으로 고치지 않는다. 장면은 `Editor/`의 메뉴 코드로 만든다.
- 기획안에 없는 것을 정해야 하면 코드에 넣기 전에 선우에게 묻는다. 숫자는 `SkirmishSettings`에 모은다.
- 헤드셋에서 본 것만 "확인됨"으로 적는다.
