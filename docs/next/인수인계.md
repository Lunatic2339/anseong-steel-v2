# 인수인계: 새 기획(고로 앞 보스전)

2026-11-27 기준. 이 브랜치(`feat/next-z2-gunship`)에서 일하는 사람과 AI가 처음에 읽는 문서입니다.
`CLAUDE.md`와 `docs/design/`의 내용(65m 로봇, 두 사람이 팔 하나씩, 맨손 보스전)은 **예전 기획**입니다. 이 브랜치에서는 이 문서가 먼저입니다. 코드 규칙과 Unity 작업 규칙은 `CLAUDE.md` 것을 그대로 따릅니다.

확인 수준: 아래의 "됨"은 테스트와 창 없는 Unity에서 찍은 사진으로 본 것입니다. **헤드셋으로 확인한 것은 하나도 없습니다.**

## 1. 무엇을 만드나

- 전시 2026-12-10. 한 판 약 5분. 처음부터 끝까지 고로 앞 한 자리에서 보스 하나와 싸운다.
- **P1 (호스트 PC, 로봇 "기체")**: 35m 로봇. 왼팔 방패로 왼쪽/오른쪽을 막고, 오른팔 검으로 벤다. 걷지 않는다.
- **P2 (접속 PC, "지원")**: 헬기 사수 자리. 연사 포, 스캔과 약점 사격(강한 탄 3발), 자폭 드론 요격.
- **보스**: 적의 로봇, 키 35, 대검 하나(방패 없음). 체력 1200. **튕겨난 동안에만** 피해가 들어간다.
- 전체 기획안은 공유 드라이브의 `team-handoff-20261126/공통/기획안-20261126.html`입니다(이 레포에는 없음). 기획이 바뀌면 선우가 알립니다.

## 2. 지금 되는 것 (보스전 1막)

| 규칙 | 값 |
|---|---|
| 보스 공격 | 왼쪽 베기 → P1 왼쪽 막기, 오른쪽 베기 → P1 오른쪽 막기. 예고 1.2초(처음 나올 때만 1.8초) |
| 막으면 | 보스가 2초 튕겨남. 닿기 0.3초 안에 막으면 3초 |
| 못 막으면 | 로봇 내구도 −15, 1.2초 뒤 다시 공격 |
| P1 검 | 튕겨난 틈에 한 번 40. 틈 밖에서는 튕긴다 |
| P2 포 | 초당 8발, 한 발 4. 틈에만 들어간다. 과열 있음 |
| P2 스캔 | 버튼(왼손 트리거)을 누른 채 포 조준을 보스에 2초 → 약점 표시 4초(등, 어깨, 옆구리 차례). 스캔 중에는 포가 안 나간다 |
| P2 강한 탄 | 표시가 떠 있을 때 약점을 겨누고 버튼을 놓으면 발사. 반지름 3 안이면 피해 90, 예고가 끊기고 4초 튕겨남. 빗나가면 한 발만 줄어든다. 한 판 3발 |
| 자폭 드론 | 12초마다 하나, 초속 16. P2가 2발로 요격하거나 P1이 막는다. 맞으면 −25 |
| 끝 | 보스 체력 800에서 1막 끝. 혼자 할 때는 900에서 시작해 600 |
| 그 밖 | 내구도 30 아래면 예고 1.3배. 내구도 0이면 재기동 한 번(3초) |

숫자는 전부 종이 위 첫 값입니다. 자동 조작 둘이 빈틈없이 하면 1막이 8.7초에 끝납니다(어림은 45초). 사람으로 재 보고 고쳐야 합니다.

## 3. 아직 없는 것

**P2 쪽**
- 이륙(로봇 발 옆에서 15초 동안 떠오름)과 멀미 확인
- 숨기(조종석 턱 아래로 숙이거나 옆으로 0.4)와 "헬기를 노림" 공격
- 등 뒤의 불(속임 베기의 색, 큰 내려베기의 불 셋). P2에게만 보여야 한다
- 자폭 떼(넷이 한꺼번에). 드론은 전부 로봇으로 온다(닿으면 25, 그쪽으로 막고 있으면 0). 고로 내구도는 없앴다(11/27). 지는 조건은 로봇 내구도 0 하나, 고로는 경고등만
- 화면 표시에서 아직 없는 것: 시야 밖 드론의 방향 화살표, 헬기를 노릴 때 가장자리 붉어짐과 아래 화살표
- 스캔할 때 센서가 보스를 향하는 것
- 헬기 자리는 (111, 40, 595), 정면 북쪽, 기수 15도 숙임으로 정해졌습니다(11/27). 15도 기운 조종석이 헤드셋에서 괜찮은지는 아직 확인 전
- 실제 두 PC와 헤드셋 두 대로 접속 확인, 90fps 확인

**P1 쪽과 공통**
- 막 전환은 들어갔습니다(11/27): 체력 800에서 2막, 400에서 3막, 60에서 끝. 한 방에 선을 넘겨도 체력은 선에서 멈추고, 막이 바뀌면 내구도가 100으로 돌아오고 날아오던 드론이 사라집니다. 2막에 들어갈 때 보스가 2초 물러서고(그동안 서로 피해 없음), 3막에 들어갈 때는 물러서는 대신 한 번 크게 내려쳐 검과 방패를 부숩니다(피해 없음, 이후 주먹). 재기동하면 하던 막의 처음부터 다시 합니다. 드론은 12초 → 10초 → 6초마다. 수치는 `SkirmishSettings`의 `acts`, `actBreakSeconds`, `breakSlowSeconds`
- 아직 없는 것: 60 아래의 마지막 공격과 마무리 일격(지금은 60에서 그냥 끝남). 2·3막의 공격은 아직 1막과 같은 좌우 베기
- 특별한 공격 다섯(속임 베기, 헬기를 노림, 자폭 떼 부르기, 큰 내려베기, 찌르며 돌진)과 옆으로 한 걸음
- 검이 부러진 모습(지금은 검과 방패가 그냥 사라짐), 부서지는 소리와 효과
- 보스 등장: 게임 안에서 걸어오지 않고 **등장 영상**(mp4, 15~20초, 선우가 만듦)을 튼다. 0.5초 어두워짐 → 영상 → 밝아지면 보스가 자리에 서 있음. 영상 파일이 없으면 어두워졌다 바로 넘어간다. 헤드셋에서 보여 주는 방법은 미정
- 대사 26줄, 결과 화면, 장면 전환
- 보스와 우리 로봇의 팔 자세는 코드로 잡은 임시입니다(Mixamo 대검 동작으로 바꿀 예정). 대검과 검은 상자입니다

## 5. 돌려 보기

- Unity 6000.3.26f1로 연다. 메뉴 `Anseong → Sandbox → Build Boss Act 1`을 누르면 장면이 새로 만들어져 `Scenes/Sandbox/Sandbox_BossAct1.unity`에 저장된다. **저장된 장면을 그냥 열지 말고 메뉴로 다시 만든다**(모델 파일이 없는 PC에서는 연결이 끊겨 있다).
- Play 뒤 시작 화면에서 1(혼자), 2(호스트 = P1), 3(접속 = P2).
- 키보드와 마우스(헤드셋 없이): 마우스로 보기, 왼쪽 버튼 = 쏘기/베기, 오른쪽 버튼 = P1 막기 또는 P2 스캔 버튼, Q/E = 왼쪽/오른쪽 막기, C = 취소. 운영자 키: R 다시 시작, Enter P2 없이 시작, B 빈 자리 자동 조작, G 혼자일 때 자리 바꾸기.
- 테스트: `Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults Logs/editmode-results.xml -logFile Logs/editmode.log`. 지금 449개 가운데 447개 통과이고, 실패 2개는 예전 기획의 `DefenseTests`입니다(이 판과 무관, 원인 미확인).
- 한 PC에서 접속 확인: `-executeMethod Anseong.EditorTools.SkirmishSandboxMenu.BuildBossAct1Player`로 실행 파일을 만들고, `AnseongBossAct1.exe -mode host -skirmishAuto 결과.json`과 `-mode client -ip 127.0.0.1 -skirmishAuto 결과.json`을 같이 띄운다. 11/27에 양쪽 모두 "1막 끝"으로 맞았다.

## 7. 같이 일하는 규칙

- 자기 브랜치를 `feat/next-z2-gunship`에서 따고(성재: `sungjae`), 푸시한 뒤 선우에게 알린다. `develop`과 `main`은 건드리지 않는다. 합치는 것은 선우가 한다.
- 규칙은 `SkirmishSession`과 `GruntDuel`에만 둔다. 화면 코드에 규칙을 넣지 않는다. 규칙을 고치면 `BossActTests`에 테스트를 붙이고 전체 테스트를 돌린다.
- `SkirmishSession.cs`, `SkirmishTypes.cs`, `SkirmishNet.cs`, `SkirmishSettings.cs`는 P1 쪽과 P2 쪽이 같이 고치는 파일입니다. 여기를 고칠 때는 미리 알리고, 한 번에 작게 고친다.
- `.unity`, `.prefab`, `.meta`를 손으로 고치지 않는다. 장면은 `Editor/`의 메뉴 코드로 만든다.
- 기획안에 없는 것을 정해야 하면 코드에 넣기 전에 선우에게 묻는다. 숫자는 `SkirmishSettings`에 모은다.
- 헤드셋에서 본 것만 "확인됨"으로 적는다.

