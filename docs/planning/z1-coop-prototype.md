## 구현 규칙

- Host/Client와 Mech/Support를 별도 취급한다. 지원이 호스트여도 메카 참가자가 양팔을 소유한다.
- 같은 안과 서로 다른 두 역할만 참가 가능. PC 지원은 XR을 자동 실행하지 않는다. VR 역할에서만 수동 OpenXR 초기화를 한다.
- 판 상태: Locked → Supported → Opening → Open. VR 접촉으로 Supported, 지원의 유효 조작으로 Opening. 성공은 한 판에서 한 번만 기록.
- 서버가 접촉·역할·표적 raycast·스캔·판 상태를 결정한다. 클라이언트의 ‘성공했다’는 플래그를 그대로 받지 않는다.
- 추적이 끊기거나 입력이0.5초 이상 오래되면 새 접촉을 인정하지 않는다. 이미 받침에 걸린 판은 유지.
- 양쪽 준비 전에는 진행하지 않는다. 연결 중단 시 판 진행을 멈추고 완료한 하중 해소/스캔/판 이동량을 보존. 재접속 후 양쪽 준비 필요.
- 메카만 R로 구역 재시작 가능. 새 epoch로 이전 명령을 무효화하고 판·스캔·드론 시작점·준비 상태를 초기화.
- 중복 순번, 이전 epoch, 잘못된 역할, 유효하지 않은 손 위치는 거부.
- 드론은 임시6m/s, 허용 영역 내 이동과 구체 스윕 충돌을 사용한다. 최종 비행 감각의 확정값이 아니다.

## 여는 법

3. 다른 실행 인스턴스는 `anseong-steel-next/Builds/Z1/AnseongZ1.exe`를 실행한다. 같은3안/4안을 선택하고 서로 다른 역할로 호스트/클라이언트를 연결한다.
4. 같은 컴퓨터는127.0.0.1, 다른 컴퓨터는 호스트의 LAN IPv4와 같은 UDP 포트를 사용한다. Windows 방화벽 허용이 필요할 수 있다. 프로그램에서 방화벽을 변경하지 않는다.
5. 양쪽 ‘준비’ 또는 Enter를 누른다. VR은 오른손 트리거로도 준비 가능.

**HMD 없이 확인:** 메카의 ‘키보드 대체 입력’을 켜고 Q=왼손 밀기, E=오른손 밀기, T 유지=추적 중단, R=초기화. 이는 VR 실기 테스트가 아니다.

**실제 VR:** 메카의 대체 입력을 끄고 PC VR/OpenXR 환경을 준비한다. 준비 시 양손 위치가 중립 기준이 되며 상대 움직임을 임시12배로 확대한다. 이동·회전은 없는 고정 조종석이다. 손목 회전/정교한 IK/정식 체형 보정은 미구현이며 현재 팔은 두 구간의 임시 형상이다. 몸을 크게 뻗어야 한다면 보정/배치를 수정해야 하며 그 자세를 요구하는 것이 아니다.

## 검증과 남는 문제

- EditMode56개 통과: 기존 기반40+신규 협동 규칙16. 실제 두 프로세스 연결 결과는 아래 후속 기록을 따른다.
- Unity6000.3.26f1 Windows x64 개발 빌드 성공. 3안(메카 호스트/지원 클라이언트),4안(지원 호스트/메카 클라이언트)을 각각 실제 두 프로세스로 localhost 연결해 자동 입력으로 완료했다. 네 실행 모두 종료코드0, Open/travel=1/releases=1, 로그 예외0. 실제 두 사람의 플레이나 두 물리 PC 검증을 대신하지 않는다.
- 메카·드론·관제 시점3장을 Unity 카메라로 렌더링해 확인했다. VR 안내가 접촉판을 가리던 문제를 줄였다. 이미지에는 화면용 IMGUI 메뉴가 포함되지 않으며 실제 HMD 렌더링과 구별한다.
- 최초 Windows 실행에서 런타임 생성 재질의 셰이더 누락을 발견해 Resources 재질로 명시하고 재빌드·연결 재검증했다. 최종 결과/로그/이미지는 새 저장소 `docs/validation/z1`에 저장한다.
- 실제 HMD 조작·멀미·양손 도달·두 물리 PC/LAN 지연·패킷 손실·성능 예산은 미검증.
- 이 장면은 기본 도형과 Built-in 렌더러를 사용하는 동작 검증용이다. 최종 URP·에셋·조명·금속음·VFX·보스·관제 EMP는 포함하지 않는다.
- 드론은 첫 사람 시점의 비행/사격 검증용 카메라다. 기획의 기체 뒤쪽 시점을 최종 철회한 결정이 아니다. 관제 K0/K1 좌표도 이 단일 장면의 임시 관측점이며 전체 맵 카메라 배치를 덮어쓰지 않는다.
- 포즈는20Hz 신뢰성 메시지를 사용한 단순 검증 구현. 최종 동작에는 비신뢰성 포즈 전송/보간·대역폭·재연결/예외 관측을 추가 검토한다. 입력 위치/시선의 위변조 방어를 완성한 출시 서버로 취급하지 않는다.
- 키보드 대체 입력과 자동 스모크 입력은 명시적 개발 도구이며 최종 전시 빌드에서는 분리해야 한다.
