## 4. 무엇을 가져올 것인가

### 지금 선별한 5개

| 코드 | 재사용 목적 | 적용 전 남는 조건 |
|---|---|---|
| `HeightFit` | 모델 높이 배율·접지 위치 계산 | 35m 리그/피벗/실제 bounds 확인. 크기만 맞춘다고 조종감이 맞지는 않음 |
| `MaterialSlotNames` | 재질 슬롯 이름 비교 | Meshy·무료 에셋의 실제 슬롯 이름/재질과 연결 필요 |
| `HandDeadzone` | 손의 작은 위치·회전 흔들림 완화 | 입력 유효성은 호출부 책임. 보정량/반응성은 HMD에서 조정 |
| `TrackingStateRules` | 위치+회전 추적 상태 확인 | 추적 끊김 시 공격 중지·복귀 안내는 별도 구현 |
| `CockpitClearZoneMath` | 조종석 영역과 물체 bounds 겹침 계산 | 보수적 상자 판정. 렌더러를 전역으로 숨기는 동작은 가져오지 않음 |

기존 테스트 5파일도 원문 그대로 가져왔다. 네임스페이스 유지, 소스 수정 없음. 기존 씬/프리팹/리그/모델/텍스처/입력 에셋/프로젝트 설정/Library는 복사하지 않았다. 새 asmdef와 package.json만 선별 코드의 의존성에 맞게 작성했다. 기존 `Anseong.Runtime` 전체와 동시에 로드하면 동일 타입이 중복되므로 새 기반을 기존 프로젝트에 통째로 추가하지 않는다.

### 다음으로 수정해서 살릴 가치가 큰 것

1. **팔 IK 묶음**: `TwoBoneArmSolver` + `ArmCalibration` + `ArmMapping` + `MechaArmStability`. 한 파일만 떼면 되지 않는다. `PilotSide`가 `CockpitSeatMath`에 정의된 결합부터 정리하고 35m 리그, 양팔, 몸통/방패 간섭, 이동 자세 전환을 검증한다. 기존 수학 테스트를 함께 이전한다.
2. **입력 처리**: `PilotHandInput`의 장치 일치·유한값 검사·그립 히스테리시스, `AttackIntentGate`의 추적 상실 처리. 새 주먹에 그립 필수 조건을 자동으로 강제하지 말고 최종 UX에 맞게 분리한다.
3. **네트워크 표현**: `PoseBuffer`의 시간 보간/오래된 표본 유지 방식, `RobotMotionSync`의 서버 시간 기반 이동 표현. 양팔/드론 데이터 구조, NaN·시간 역행·비정상 미래 시간·재접속 초기화를 추가 검토한다. 기존 NetworkBehaviour 통째 복사는 보류한다.
4. **전투 흐름**: `CombatAuthority`의 순수 규칙과 서버 실행 분리, `BossAttackStateMachine`의 예고→공격→회복 시간 처리. 좌우 콤보/부스트를 포함한 현 클래스는 그대로 채택하지 않는다.
5. **개발 도구**: 튜닝·CSV 로그·에디터 생성 메뉴의 방식. 데이터가 필요한 지표만 남기고 새 역할/에셋 명명에 맞게 만든다.

복잡한 펀치 분류·좌우 콤보·합동 피니셔·두 스틱 회피는 현재 새 게임의 필수 기능이 아니므로 보류한다. 기존 테스트는 유용한 행동 기록이지만, 통과한다고 새 게임 규칙에 맞는 것은 아니다.

## 6. 다음 작업과 통과 기준

**다음 추천은 전체 맵 제작보다 작은 협동 검증 장면 하나다.** 바닥, 35m 메카 임시 리그, 출격판 한 개를 사용하고 같은 사건에 드론 모드와 관제 모드를 붙인다. 실제 제작 시작 범위는 이 검토 결과를 기준으로 이어간다.

1. VR 양팔 조작을 먼저 분리하고 PC 지원 접속으로 양팔 소유권이 변하지 않는지 확인.
2. PC3 드론 조준/해제와 PC4 카메라/해제를 같은 판 상태에 연결. 양쪽 화면에서 원인과 결과가 읽혀야 함.
3. VR 추적 중단, PC 연결 중단, 중복 입력, 구역 재시작을 시험. 판 해제/낙하 같은 사건이 두 번 실행되지 않아야 함.
4. 두 프로세스 테스트 후 실제 VR+PC 두 기기에서 입력 반응·원격 팔·시야·멀미·대기를 측정. 솔로 성공만으로 통과 처리하지 않음.
5. 작은 장면이 통과하면 Z2 갑각과 Z3 크레인을 확장. 목표기기·실행 구성·프레임 예산은 실제 장비 확인 후 결정.
