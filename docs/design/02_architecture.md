# 02 기술 구조

## 장비

| PC-A (호스트 · 왼쪽 조종사) | PC-B (클라이언트 · 오른쪽 조종사) |
|---|---|
| Quest 3 (Link 유선) | Quest 3 (Link 유선) |
| 왼팔 외골격 ESP32 (USB 시리얼) | 오른팔 외골격 ESP32 (USB 시리얼) |
| 관객용 모니터(선택) | 관객용 모니터(선택) |

두 PC는 유선 LAN(스위치 또는 직결)으로 연결한다. 학교 와이파이에 의존하지 않는다.

헤드셋 연결:
- **시연은 유선 Link가 기본.** USB-C 3.0 Link 케이블 약 5m × 2(+예비 1). 헤드셋 선과 외골격 USB 선을 묶어 한 줄로 PC까지.
- **Air Link는 예비.** 개발 중에는 써도 된다(게임 코드는 유선·무선 구분 없음). 시연 당일 케이블 고장 시 전환하며, 이를 위해 PC에 랜선으로 연결한 전용 공유기를 챙긴다.
- 무선을 기본으로 하지 않는 이유: 시연장 와이파이 혼잡(헤드셋 2대 동시), 외골격 USB 선 때문에 조종사가 어차피 PC에 연결됨, 하루 종일 시연 시 배터리, 추가 지연.
- M6 테스트 때 가능하면 시연 장소에서 Air Link도 한 번 돌려본다.

## 누가 무엇을 계산하나

| 계산 | 위치 | 전송 |
|---|---|---|
| 자기 조종사 입력·보정·팔 IK·주먹 포즈 | 각 PC 로컬 | 자기 팔은 네트워크를 거치지 않음 |
| 머리·양손 자세 | 각 PC가 소유 | 비신뢰(Unreliable) 60Hz → 상대 PC가 100ms 버퍼로 보간해 그림 |
| 펀치 궤적 분류 + 주먹 접촉 | 때린 쪽 PC | `HitReport(side, kind, quality, clientTime, strikeId)` 신뢰 RPC → 서버 |
| 가드 상태 | 각 PC가 자기 팔 | 매 틱 owner-write 값 |
| 연계·부스트·피해·HP·페이즈 | 서버(PC-A) | NetworkVariable + 서버 → 클라이언트 이벤트 RPC |
| 보스 AI·공격 판정 | 서버 | 상태(공격 종류 + 시작 서버 틱) 복제 → 클라이언트는 같은 시점부터 애니메이션 재생 |
| 외골격·컨트롤러 진동 | 각 PC가 자기 장치만 | 로컬 명중 + 서버 이벤트 |

NGO 설정: Unity Transport 직결(`SetConnectionData(ip, 7777, "0.0.0.0")`), 틱 60. 승인 콜백에서 3번째 접속 거절. 클라이언트는 피해·HP를 직접 쓰는 RPC를 갖지 않는다. 서버는 보낸 클라이언트가 그 팔(side)의 소유자인지 검사한다.

**1인 양팔 모드**: 같은 코드를 한 PC가 호스트로 실행하며 양쪽 조종사를 모두 로컬로 맡는다. 네트워크 경로와 판정 경로가 같아야 한다(별도 오프라인 전용 규칙 코드를 만들지 않는다).

## 시점과 스케일

- 월드는 실제 크기. v026 모델은 임포트 시 약 1m라서 약 65배(임포트 후 실측해 맞춤). 보스도 같은 크기.
- XR Origin은 **확대하지 않는다**. 조종사는 사람 크기 그대로 로봇 머리 높이 조종석에 선다(M0에서 가슴 상단과 비교 후 확정).
- 팔 매핑: `로봇 주먹 목표 = 로봇 어깨 + (손 − 보정한 사람 어깨) × (로봇 팔 길이 ÷ 개인 팔 길이)`. 눈이 어깨 근처라서 각도가 보존된다. 배율 약 35~40배.
- 조종석은 실제 형상(바닥, 콘솔, 창틀). 렌더텍스처 중계 화면을 쓰지 않는다. 두 좌석 간격 = 실제 바닥 테이프 간격.
- 조종사 카메라는 절대 지연시키지 않는다. 로봇의 묵직함은 팔 반응(가속·감속)으로 표현한다.
- 고개를 돌려도 팔의 정면 기준은 돌지 않는다(보정 시 저장한 몸 정면 기준).

## 팔 IK 요구사항

- 해석적 2본 IK. 팔꿈치 swivel은 컨트롤러 회전에서 연속 각도로 고르고 범위 제한 + 히스테리시스.
- 손목은 전완에 고정(손목만 꺾이는 펀치 방지). 그립을 놓으면 제한된 손목 회전 허용.
- 매 프레임 바인드 포즈 기준으로 **절대 재구성**(누적 회전 금지 → roll 드리프트 방지).
- 손이 팔 길이 밖이면 지수형으로 부드럽게 한계에 수렴. 너무 가까우면 내부구 처리.
- 어깨·팔꿈치가 180도 돌아가는 현상이 없어야 한다.
- 손가락은 펀치 상태에서 주먹 고정.

## 외골격 시리얼 프로토콜 (제안)

- 115200bps, 한 줄 ASCII: `R,<세기 0-255>,<지속ms>\n`. 예: `R,180,120`.
- 펌웨어: 200ms 동안 명령이 없으면 출력 0(워치독). 하드웨어 전류 제한 + 기계적으로 풀리는 안전장치 필수.
- Unity: 별도 스레드에서 포트 쓰기, 포트가 없거나 끊기면 조용히 비활성(게임 진행 영향 없음). Api Compatibility Level = .NET Framework.

## 성능 목표

- Link에서 90fps 유지(72fps 하한). GPU 여유를 위해 외부 카메라 추가 렌더 없음.
- v026 모델은 SkinnedMeshRenderer 291개·재질 124개 → 수십 개 이하로 병합, 텍스처 아틀라스.
