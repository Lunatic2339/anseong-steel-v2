# 04 아트 사양서

아트는 아직 미완성이다. 이 문서는 **코드와 아트가 서로를 기다리지 않도록** 지켜야 할 기준과, 처음 해보는 사람도 할 수 있게 쪼갠 작업 목록이다. 수치는 제안값이며 총괄 채팅에서 바꿀 수 있다.

## 결정된 것

- 보스·플레이어 모두 **v026 디자인**. 같은 모델을 색·발광으로 구분한다.
- 손가락은 **주먹으로 고정**. 코드가 주먹 포즈를 씌우므로 손가락 애니메이션은 만들지 않는다.
- 플레이어 로봇 팔은 IK로 움직이므로 **플레이어용 애니메이션은 필요 없다**(출격 자동 걷기 정도만 보스 클립 재사용).
- 모델 전용 텍스처를 새로 그리지 않는다. 단색 플라스틱처럼 보이지 않게 **반복 디테일 맵·AO·색 슬롯**을 쓰거나 기존 Tripo 텍스처를 살린다. 최종 방식은 A-03에서 헤드셋으로 3안을 비교해 고른다(아래 "표면 표현 3안").
- 팀에 Blender 경험자가 있으므로 **메시 병합·재질 교체·모서리 정리는 Blender에서** 원본을 깨끗하게 만든다(A-02). Blender가 막히면 Unity 에디터 도구로 대신한다.

## 바꾸면 안 되는 기준 (코드가 의존함)

| 항목 | 기준 |
|---|---|
| 원본 파일 | M0-03에서 확정: `Assets/_Anseong/Art/Robot/Source/BossUpdatedCompatible.fbx` (v026 디자인, 텍스처 122장은 같은 폴더 `Textures/`) |
| 뼈대 | 위 파일의 Mixamo 뼈(`mixamorig:` 접두사). 뼈 이름·계층·개수를 바꾸지 않는다 |
| 비율 | 팔 길이(어깨–팔꿈치–손목) 비율을 바꾸지 않는다. 바꿔야 하면 먼저 총괄에 알린다 |
| 크기·단위 | 원본은 **단위 m, `Armature` 스케일 1**, 임포트 높이 약 1.056m. 65m 배율(약 61.55)은 씬에서 적용한다. M0-03에서 단위 cm·`Armature` 스케일 100인 파일은 Idle 재생 시 몸이 사라졌다. 다시 내보낼 때 반드시 같은 단위·스케일 |
| 정면 | 모델 정면 = Unity +Z, 위 = +Y |
| 다시 내보내기 | 모양을 고쳐서 다시 내보낼 때도 위 기준이 같으면 파일만 교체하면 된다 |

## 성능 한도 (로봇 1기, PC Link 90fps 목표)

| 항목 | 한도 | 현재 v026 |
|---|---|---|
| 삼각형 | 80,000 이하 | 약 59,134 (통과) |
| SkinnedMeshRenderer | 8개 이하 | 291개 (**병합 필요**) |
| 재질 | 6개 이하 | 124개 (**교체 필요**) |
| 텍스처 | 장당 2048 이하(아틀라스는 4096 1장까지) | 1024 이하 122장 (메시를 합치면 아틀라스 1장으로 다시 굽거나 버려야 함) |

로봇 2기 + 조종석 + 환경 전체가 화면에 동시에 나온다는 기준이다.

## 현재 모델의 문제와 해결 순서

| 문제 | 원인(추정) | 해결 순서 |
|---|---|---|
| 가까이서 텍스처가 번짐 | Tripo AI 생성 텍스처. 해상도가 낮고 장갑 경계·볼트가 그림으로만 흐릿하게 칠해짐 | 반복 디테일 맵(긁힘·패널·금속 결)을 겹쳐 가까이서도 선명하게. Tripo 텍스처를 버릴지 살릴지는 "표면 표현 3안"에서 비교 |
| 텍스처를 빼면 둥글둥글함 | 폴리곤 수가 아니라 **노멀 스무딩**: 모든 모서리가 부드럽게 이어지게 처리돼 각진 판도 비누처럼 보임. 폴리곤 수(약 5.9만)는 문제가 아님 | 1) 임포트 설정 Normals = Calculate, Smoothing Angle 30~45° 비교 → 2) URP SSAO + 강한 방향광으로 판 사이 명암 → 3) 그래도 안 되면 Blender Decimate(Planar)로 면 정리(뼈 가중치 재확인 필요, 마지막 수단) |

조종사 눈은 로봇 머리 높이, 보스는 약 40m 앞이다. **가까이서 보는 디테일보다 실루엣·명암 대비·금속 반사**가 우선이다.

## 표면 표현 3안 (A-03에서 헤드셋으로 비교)

텍스처를 그냥 빼면 단색 플라스틱처럼 보인다. 그래서 아래 세 가지를 같은 장면에서 비교해 고른다.

| 안 | 구성 | 장점 | 비용 |
|---|---|---|---|
| 가 | Tripo 텍스처 그대로 | 지금 색감 유지 | 가까이서 번짐. 메시를 합치려면 Blender에서 텍스처 122장을 아틀라스 1장으로 다시 구워야 함 |
| 나 | 색 슬롯 6개 + 반복 디테일 맵 + AO | 가까이서도 선명, 재질 수 적음, 보스·플레이어 색 바꾸기 쉬움 | Tripo 색감은 사라짐. AO 굽기는 Blender 작업 |
| 다 | Tripo 텍스처(아틀라스) + 반복 디테일 맵 | 색감 유지 + 선명함 보완 | 아틀라스 굽기 + 디테일 맵 둘 다 필요 |

- 반복 디테일 맵: URP Lit 재질의 Detail Inputs(Detail Map·Detail Normal, 타일링)로 넣는다. 셰이더를 새로 만들 필요 없음. 무료(CC0) 금속·패널·긁힘 텍스처를 쓴다.
- AO: Blender에서 판 사이 틈 그림자를 텍스처나 버텍스 컬러로 굽는다. 단색 느낌을 줄이는 효과가 가장 크다.
- 보스와 플레이어 구분: 가안이면 텍스처 색을 바꾸기 어려우므로 발광색·일부 슬롯 색으로 구분한다.

## 공용 재질 슬롯 (제안)

| 슬롯 | 용도 | 플레이어 색(제안) | 보스 색(제안) |
|---|---|---|---|
| ArmorMain | 큰 장갑판 | 흰색·밝은 회색 | 검정 |
| ArmorAccent | 포인트 장갑 | 파랑 | 빨강 |
| Metal | 관절·프레임 | 금속 회색 | 어두운 금속 |
| Dark | 안쪽 기계·틈 | 짙은 회색 | 짙은 회색 |
| Glow | 발광부(눈·라인) | 하늘색 발광 | 노랑·주황 발광 |
| Trim | 테두리·장식 | 은색 | 무광 금색 |

URP Lit 재질 6개 × 2세트(플레이어/보스). 색·Metallic·Smoothness·Emission만 쓴다. 최종 색은 윤주가 정한다.

## 보스 애니메이션 목록

플레이어 로봇과 같은 Mixamo 뼈라서 **Mixamo에서 받은 클립을 그대로 쓸 수 있다**. 이미 있는 것은 기존 레포 `AnseongSteel/Assets/_BossPrototype/Animation/` 아래에 있다.

| 우선 | 필요한 동작 | 쓰는 곳 | 상태 | Mixamo 검색어 예시 |
|---|---|---|---|---|
| 1 | 전투 대기 | 항상 | 있음 `Idle.fbx` | – |
| 1 | 오른손 펀치 | 일반 공격 | 있음 `Punch.fbx` | – |
| 1 | 왼손 펀치 | 일반 공격 | **필요** | punch, jab, hook (왼손 버전) |
| 1 | 피격 경직 | 가드 성공·반격 | 있음 `CombatSource/Stagger` | – |
| 1 | 크게 밀려남 | 부스트 명중 | **필요** | hit reaction, knocked back, big hit |
| 2 | 좌우 연타 | 2페이즈 | 있음 `CombatSource/AlternatingCombo` | – |
| 2 | 두 손 내려찍기 | 강공격 | **필요** (`GroundCast`가 쓸 만한지 먼저 확인) | ground slam, smash, hammer |
| 2 | 돌진 | 가드 불가 | **필요** | charge, tackle, shoulder, run |
| 2 | 무릎 꿇기 | HP 10% 필살기 대기 | **필요** | kneel, defeated, exhausted |
| 2 | 쓰러짐 | 승리 | 있음 `CombatSource/Death` | – |
| 2 | 앞·뒤 걷기, 제자리 회전 | 거리 조절 | 있음 `Walk`, `TurnLeft`, `TurnRight` (뒤 걷기는 필요) | walking backward |
| 3 | 등장 포효·도발 | 전투 시작 | 선택 | taunt, roar, battlecry |

받는 설정: **Format = FBX for Unity, Skin = Without Skin, 30fps**, 걷기·달리기처럼 이동하는 클립은 **In Place 체크**(이동은 코드가 한다). 파일 이름은 `Boss_<동작>.fbx` (예: `Boss_PunchLeft.fbx`).

왼손 버전이 Mixamo에 없으면 오른손 버전만 받아도 된다. 좌우 반전은 M2에서 코드 쪽(Humanoid 설정 등)으로 처리를 검토한다.
