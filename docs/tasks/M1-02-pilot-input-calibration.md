## Claude가 할 일
1. `PilotInput.inputactions`에 손별 `Grip`, `Trigger`, `Stick` 액션 추가.
2. `Runtime/Pilot/PilotHandInput.cs`: 손 하나의 자세·추적·그립·트리거·스틱을 같은 프레임에 읽어 구조체로 내놓는다. 담당 팔(`PilotSide`)과 이동 손(반대 손)을 구분한다. 1인 양팔 모드에서는 양손이 모두 담당 팔이고 스틱은 둘 다 이동 입력이다.
3. 순수 클래스 `AttackIntentGate`: 그립 유지 + 추적 유효일 때만 공격 의도. 추적이 끊겼다 돌아오면 그립을 한 번 놓기 전까지 무효. 짧은 끊김이 연계를 끊지 않도록 "무효"와 "연계 초기화"는 분리한다(연계는 M1-05).
4. 순수 클래스 `ArmCalibration`: 위 기존 로직을 새 구조로. 저장값 = 어깨 위치, 가드 위치, 도달 거리, 개인 팔 길이, **몸 정면 yaw**(고개를 돌려도 팔 정면 기준이 돌지 않게). 값은 그 판 동안만 메모리에 둔다(재시작하면 초기화).
5. `Runtime/Pilot/PilotCalibrationFlow.cs`: 어깨 → 가드 → 도달 단계, 단계마다 그립 놓기. 1인 양팔 모드는 양손을 같은 단계에서 동시에 보정한다. 진행 안내는 개발용으로 Console 로그 + 선택 시 기즈모(구 모양)만. 관객용 안내 화면은 M4.
6. EditMode 테스트: `AttackIntentGate`(유실 → 복구 → 그립 놓기 전까지 무효), `ArmCalibration`(기존 레포 `ArmMotionValidation.cs` Core() 40-92의 경우를 옮김).

## 결과 (작업 후 Claude가 작성)
- 작업 브랜치: `claude/m1-cockpit-input-x0vygh` (M1-01 다음 커밋).
- 정한 것(지시서에 없던 부분):
  - **어깨 단계 = 똑바로 서서 팔을 아래로 편하게 내리고 그립.** 어깨 = 내린 손의 수평 위치 + (머리 높이 − 0.25 m), 개인 팔 길이 = 어깨 → 내린 손. 기존 레포는 반대 손을 어깨에 대는 방식이었는데, 1인 양팔 모드에서 양손을 동시에 보정할 수 없어서 바꿨다. 머리 회전은 쓰지 않는다.
  - **몸 정면 yaw = 도달 단계에서 어깨 → 뻗은 손의 수평 방향.** 머리 방향을 쓰지 않으므로 고개를 돌린 채 보정해도 몸 쪽을 가리킨다. 1인 양팔 모드는 손마다 따로 저장하고 두 값의 차이를 로그에 낸다.
  - 기본은 1인 양팔 모드(`PilotHandInput.controlsBothArms` = 켬). 2인 모드에서는 `armSide` 손만 보정·공격하고 반대 손 스틱만 이동 입력이다.
  - 그립은 아날로그 값에 히스테리시스(0.6 쥠 / 0.4 놓음). 보정 단계는 쥐는 순간 한 번 저장하고, 실패해도 놓았다 다시 쥐어야 한다.
  - 개발용 다시 보정: 왼손 Y 버튼 또는 키보드 R (`Dev/Recalibrate`).
- 세 자세 안내(관객용 안내 M4에도 쓸 것):
  - 어깨: 힘을 빼고 팔을 허벅지 옆으로 내린다. 손이 어깨 바로 아래라고 보고 계산하므로 팔을 벌리면 어깨가 바깥으로 잡힌다. **정확해야 함.**
  - 가드: 편한 복싱 가드면 아무 자세나 된다. 이 손 위치가 곧 로봇 가드 위치가 된다. 도달보다 확실히 가깝기만 하면 된다.
  - 도달: 어깨 높이에서 정면으로 곧게 끝까지 뻗는다(양손은 나란히). 이 방향이 몸 정면, 이 거리가 로봇 팔이 다 펴지는 거리다. **정확해야 함.**

- 1차 헤드셋 확인 (선우, 2026-10-17): 양손 3단계 끝까지 완료. 어깨 높이 1.36 m, 팔 길이 0.56/0.57 m, 가드 0.33/0.31 m, 도달 0.48/0.51 m. 손마다 잰 몸 정면이 왼손 +16°, 오른손 −16°로 안쪽으로 벌어짐(머리 −3°) → 어깨 추정이 좌우로 넓게 잡힌 것. **1인 양팔 모드는 두 손을 잇는 선에 수직인 공통 정면을 쓰도록 수정**(테스트 2개 추가).
- 2차 헤드셋 확인 (선우, 2026-10-17): 공통 몸 정면 −2°(손마다 잰 값 +13°/−16°, 머리 0°) → 정상. 어깨 높이 1.45 m(1차 1.36 m), 팔 길이 0.57/0.54 m, 도달 0.46 m. 손목은 1차 펀치 자세(엄지 안쪽), 2차 엄지 위로 했는데 위치 결과에는 영향이 거의 없다. 저장한 손목 회전은 M1-03 주먹 방향 기준이 되므로 **도달 단계는 펀치 자세로 통일**할 것.
- 남은 문제 / 제안:
  - 도달 거리(약 0.5 m)가 실제 팔보다 짧게 나온다. 내린 손이 실제 어깨보다 조금 앞에 있어 어깨가 앞쪽으로 잡히는 것으로 보인다. 매핑은 같은 어깨 기준으로 계산하므로 "끝까지 뻗음 = 로봇 팔 다 폄"은 그대로 맞지만, M1-03에서 팔을 움직여 보고 어색하면 어깨 추정 방식을 다시 본다.
  - 선우는 로봇 시야를 위해 가드를 평소보다 넓게 잡는다. 가드 위치가 곧 로봇 가드라 그대로 반영된다. M1-06 가드 판정은 고정 자세가 아니라 이 개인 가드 기준으로 범위를 잡을 것을 제안.
  - 어깨 높이가 두 번 보정에서 9 cm 달랐다(1.36 → 1.45 m). 어깨 단계에서 머리를 숙이면 낮게 잡힌다. 안내에 "정면을 보고"를 넣고, M1-03에서 어긋나 보이면 다시 본다.
  - 어깨 높이 추정(눈 − 0.25 m)은 사람마다 다르다. Head 좌석은 눈이 로봇 어깨보다 약 5 m 높으므로, 이 값과 함께 M1-03에서 어깨 높이 보정 항목으로 조절한다.
  - `00_plan.md` 기체 점검의 첫 단계 "담당 팔 들기"를 "팔 내리기"로 바꿀지 팀 회의에서 정할 것(관객용 안내 M4 전에).
  - 보정 중 공격 의도는 막지 않는다(펀치 판정이 아직 없음). M1-05에서 보정 완료 전 공격을 무시할지 정한다.
