# 완성 작업판 (파트별 스레드 나누기)

선우 11/13: "조금 체계적으로 개발하자. 모델링·애니메이팅·맵 제작·시나리오 등 파트별로 모듈화해서 스레드별로 만들고 서로 소통하면서." 이 문서가 파트 경계와 공통 규칙이다. 각 파트의 할 일 목록은 아래 표에서 시작해 그 스레드가 자기 칸을 고친다.

## 완료 단계 (모든 파트 공통, 건너뛰지 않는다)

| 단계 | 뜻 |
|---|---|
| 1 코드·에셋 | 파일이 있고 브랜치에 올라감 |
| 2 컴파일 | PC에서 `error CS` 없음, EditMode 테스트 통과 |
| 3 실전 판 | 장면을 건너뛰지 않는 자동 플레이 한 판에서 실제로 일어남(로그) |
| 4 화면 | 캡처·영상으로 봤을 때 싸 보이지 않음 |
| 5 헤드셋 | 선우가 써 보고 확인(Claude는 이 단계를 채우지 않는다) |

"완료"는 4단계까지다. 표에는 지금 단계 숫자를 적는다. 기존 마일스톤 체크 표시는 근거로 쓰지 않는다.

## 공통 규칙

- **요청은 받는 파트 스레드에 직접 보낸다.** "무엇이 / 왜 / 어떤 이름·형식으로 / 어디에 넣을지"를 적는다. 답은 푸시한 커밋으로 한다.
- **남의 파트 파일은 고치지 않는다.** 꼭 필요하면 그 스레드에 요청한다. 예외: 컴파일 에러를 고치는 한두 줄(고친 뒤 알린다).
- **`CombatCue`·`BossState`·`MatchScene` enum은 맨 끝에만 추가**하고 주석으로 뜻을 적는다(순서를 바꾸면 저장된 값이 틀어진다).
- **브랜치**: 각 스레드는 자기 브랜치에 푸시하고, 통합 스레드가 `claude/project-thread-1p3nc5`로 합친다. 합치기 전에 그 스레드가 최신 통합 브랜치를 rebase 한다. develop·main에는 푸시하지 않는다. PR은 선우가 "PR 올려" 할 때.
- **PC는 하나다.** Unity 배치는 폴더 하나에 한 번에 하나만 돈다. 각 스레드는 자기 워크트리(`..\anseong-<파트>`)를 쓰고, 선우 작업 폴더는 읽기만 한다. Cascadeur(스크립트 서버 127.0.0.1:8765)는 애니메이팅 스레드만, Blender 배치는 모델링 스레드가 우선. 선우가 PC를 쓰는 중이면 창을 띄우거나 소리를 내지 않는다.
- **씬·프리팹은 메뉴 스크립트로만** 만든다. `Main.unity`는 통합 스레드가 `Build Full Game`으로 다시 만들어 커밋한다. 다른 스레드는 자기 메뉴가 그 흐름에서 불리게만 한다.
- **키·결제**: API 키는 PC 환경 변수에만. 추가 결제 금지. AI 생성은 12/08까지.
- 재미 기준과 대본 대조는 `docs/design/14_scenario_changes.md`.
