## 한눈에 보기

고건님은 **외골격(포스 피드백) 전담**입니다. Unity는 만지지 않습니다. 게임 쪽 코드와 ESP32 펌웨어 초안은 선우·Claude가 쓰고, 고건님은 장치를 만들고 보드에 올려 시험하고 측정합니다. 자세한 근거는 함께 드린 PDF「외골격 진행 평가와 설계 가이드」에 있고, 이 문서는 **무엇을 어떤 순서로 하는지**만 적습니다.

외골격은 "있으면 더 좋은 것"입니다. 고장 나도 게임은 컨트롤러 진동만으로 끝까지 돕니다. 그러니 **크고 복잡한 장치보다 작고 확실하고 안전한 장치**가 목표입니다.

### 확정된 것

- 힘 방향: **펼 때 막힘**(펀치는 팔을 펴는 동작이라 명중감이 여기서 나옴). 10/16 확정.
- 장치 구성: 조종사 한 명당 **담당 팔 하나**. 조종사 A = 왼팔, B = 오른팔(왼팔 장치의 좌우 대칭). 담당 팔 손에 Quest 컨트롤러를 쥐고, 반대 손은 비워 둡니다.
- 순서: **책상 위 시제품 먼저**, 착용형은 그 다음.
- 연결: 각 PC가 자기 ESP32를 USB 시리얼(115200bps)로 제어.

### 결과물 (레포 `Hardware/Exo/`에 모음)

- 동작한 펌웨어 코드 + 배선 사진(기준본)
- 부품 목록, 출력 기록표(부품 ID·날짜·재료)
- 시험 기록(T1~T7), 특히 세기표와 지연값
- 중간발표 영상 30초

파일을 레포에 올리는 것이 어렵으면 구글 드라이브 팀 폴더에 올리고 팀 단톡방에 알려 주세요. 코드 담당(선우)이 레포로 옮깁니다.

### 시작하기 전에 팀 회의에서 정할 것

1. **예산**: 비상 정지 스위치, 퓨즈, 수하물 저울, 바닥판·클램프, 608 베어링 같은 작은 부품 값. 누가 결제하고 한도가 얼마인지.
2. **모터 개수**: 지금 PM28이 몇 개 있는지. 두 번째 장치까지 만들려면 모터·ESP32·드라이버가 한 벌 더 필요합니다.
3. **작업 장소와 3D 프린터**: 출력은 어디서 하는지, 책상 시제품을 둔 자리에 PC를 연결해 시험할 수 있는지.
4. **펌웨어 받는 방법**: Claude가 쓴 펌웨어를 레포에서 받을지, 파일로 받을지. 고건님이 쓰는 개발 도구(Arduino IDE인지 PlatformIO인지)도 알려 주세요.
5. **지금 출력 중인 부품**: 어떤 부품 ID를 이미 뽑았는지 목록을 먼저 팀 단톡방에.
