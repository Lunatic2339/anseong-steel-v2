# 조원별 지시서

처음이면 레포 맨 위 [README](../../README.md)(받는 법, 공통 규칙, AI 쓰는 법)부터 읽으세요. 파일이 어디 있는지, 결과물을 어디에 넣는지는 [폴더 지도](../폴더_지도.md)에 있습니다.

사람마다 폴더가 하나씩 있고(`<이름>/README.md`가 처음 화면, 나머지는 주제별 파일), **이 폴더들이 각자 지시서의 원본**입니다. 예전 Claude Docs 문서(10/16판)는 기록으로만 남기고 더 이상 고치지 않습니다. 예전 PDF는 지웠습니다(Git 기록에는 남아 있음).

| 사람 | 맡은 일 | 파일 |
|---|---|---|
| 선우 | Unity 코드(Claude와 같이), `Main.unity`, PC-A, 팀 회의 안건 | [선우/](선우/README.md) |
| 유진 | 보스 애니메이션·패턴·색, 중간발표 자료 | [유진/](유진/README.md) |
| 성재 | PC-B·장비, Blender 로봇 정리, 플레이어 색, 조종석 모델 | [성재/](성재/README.md) |
| 윤주 | 제철소 맵 배치, 효과음 모으기 | [윤주/](윤주/README.md) |
| 고건 | 외골격(포스 피드백) | [고건/](고건/README.md) |

## 보는 법

- 휴대폰이나 PC 브라우저에서 GitHub 레포 → `docs` → `members` → 자기 이름 파일을 누르면 됩니다.
- 맨 위 **"지금 할 일"** 과 **"다른 작업에서 온 요청"** 만 먼저 보면 됩니다. 아래는 자세한 순서입니다.
- 파일이 바뀌었는지는 맨 위 "마지막 수정" 날짜와 "바뀐 기록"으로 확인합니다.

## 각 파일의 칸

| 칸 | 내용 |
|---|---|
| 지금 할 일 | 지금부터 다음 마감까지 할 일. 관련 작업 지시서(`docs/tasks/`) 링크 |
| 다른 작업에서 온 요청 | 코드 작업(마일스톤) 중에 "이 사람이 이걸 해 줘야 한다"가 생기면 여기에 쌓임 |
| 문제·질문 보고 | 막혔을 때 어떻게 알리는지 (아래 "문제 보고하는 법") |
| AI 활용 안내 (유진·성재·윤주) | 할 일마다 AI에 맡겨도 되는 것, 직접 해야 하는 것, 요청 예시 문구 |
| 작업 노트 (`작업_노트.md`) | 내 작업 설명, 질문, 내 판단으로 바꾼 것. Claude가 답함 (아래 "작업 노트") |
| 바뀐 기록 | 언제 무엇이 바뀌었는지 한 줄씩 |
| (선우만) 팀원이 보고한 문제 → 코드 담당이 할 일 | 팀원이 올린 문제·수정 요청과, 그걸 고치려고 코드 쪽에서 할 일 |

## 문제 보고하는 법

막혔거나, 이상한 점을 찾았거나, 받은 파일·지시가 틀린 것 같으면 **팀 단톡방**에 아래처럼 올립니다. 혼자 30분 넘게 붙잡지 않습니다.

```
[문제] 이름 / 지시서 번호(예: A-02 1단계)
무엇을 하다가: 
무슨 일이 생겼나: 
화면 캡처: (첨부)
```

그다음은 코드 담당(선우)이 총괄 채팅(Claude)에 이 글을 넘기고, Claude가 이렇게 정리합니다.

1. [선우/README.md](선우/README.md)의 "팀원이 보고한 문제 → 코드 담당이 할 일"에 한 줄 추가 (날짜, 보고한 사람, 내용, 코드 쪽에서 할 일).
2. 고치는 과정에서 그 팀원(또는 다른 팀원)이 다시 해야 할 일이 생기면, 그 사람 파일의 "다른 작업에서 온 요청"에 한 줄 추가.
3. 고쳐지면 두 줄 모두 상태를 "끝남"으로 바꾸고, 팀 단톡방에 "고쳤어요, 내 파일 확인해 주세요"라고 알립니다.

GitHub에 익숙하면 자기 파일에서 연필(✏️) 버튼을 눌러 직접 적어도 됩니다. 그래도 팀 단톡방에는 한 줄 알려 주세요.

## 작업 노트 (질문·변경을 Claude에게 묻기)

각자 폴더의 `작업_노트.md`는 내 작업을 설명하고 Claude에게 묻는 곳입니다.

**팀원이 하는 일**
1. `작업_노트.md` 맨 위 "노트" 아래에 양식대로 씁니다. `[질문]`, `[변경]`(내 판단으로 바꾼 것), `[설명]` 중 하나.
2. 작업한 파일과 **같이 커밋**해서 내 이름 브랜치에 푸시합니다. 커밋 설명 맨 앞에도 `[질문]`이나 `[변경]`을 붙이면 찾기 쉽습니다(예: `[변경] A-02 각도 40°로`).
3. 팀 단톡방에 알립니다.
```
[질문] 또는 [변경] 이름 / 지시서 번호
작업 노트에 적었어요: (제목 한 줄)
```
4. 답이 올라오면 단톡방에 "답 올렸어요"라고 알려 드립니다. 작업 전에 GitHub Desktop **Pull origin**(또는 Claude Code에 "내 브랜치 최신으로 받아줘")을 누르면 내 노트에 답이 보입니다.

**답이 나오는 과정**
1. 코드 담당(선우)이 총괄 채팅(Claude)에 "○○ 작업 노트 봐줘"라고 넘깁니다.
2. Claude가 노트와 같이 올린 파일, 지시서, 기획 문서를 보고 **답 초안**을 씁니다. `[변경]`이면 괜찮은지(그대로 / 조건부로 괜찮음 / 되돌리기) 이유와 함께 판단합니다.
3. **코드 담당(선우)이 초안을 보고 허락하거나 고쳐 달라고 합니다.** 허락 전에는 아무것도 올라가지 않습니다.
4. 허락받은 답을 Claude가 그 노트 아래 `> Claude 답변:`에 적고, 상태를 `답변함`으로 바꿔 내 이름 브랜치에 커밋합니다.
5. 결정이 필요한 것(돈, 방향, 고르기)은 답 대신 "팀 회의에서 정할 것"으로 남깁니다.

## Claude 세션이 지킬 규칙

이 프로젝트의 모든 Claude 세션(총괄 채팅, 마일스톤 작업 스레드, Claude Code)은 아래를 따른다.

1. **팀원에게 원하는 것이 생기면** (마일스톤 작업 중 아트·장비·소리·외골격 쪽 요청, 지시서 변경) 그 팀원 파일의 "다른 작업에서 온 요청" 표 **맨 위**에 한 줄을 넣는다.
   - 형식: `| 날짜(MM/DD) | 어디서(작업 이름, 예: M1-05 명중 판정) | 요청(처음 하는 사람도 알 수 있게 무엇을·왜·어디에 넘기는지) | 새 요청 |`
   - 지시서(`docs/tasks/`)를 바꿔야 하는 요청이면 그 지시서도 같이 고치고 링크를 건다.
   - 그 파일의 "지금 할 일"에 영향이 있으면 같이 고친다.
2. **팀원이 문제를 보고하면** `선우/README.md`의 "팀원이 보고한 문제" 표 맨 위에 넣고, 코드 쪽 할 일을 적는다. 고친 결과 팀원에게 다시 부탁할 일이 생기면 1번대로 그 팀원 파일에도 넣는다.
3. 고친 파일의 "마지막 수정" 날짜를 바꾸고 "바뀐 기록"에 한 줄(날짜: 무엇을, 왜) 추가한다.
4. 상태 값은 `새 요청` / `하는 중` / `끝남` 세 가지. 끝난 줄은 지우지 않는다.
5. 쉬운 한국어로 쓴다. 결정이 필요한 것은 "팀 회의에서 정할 것", 질문·파일 전달은 "팀 단톡방"으로 쓴다.
6. **한 파일에는 한 주제만.** 새 일이 생기면 그 사람 폴더에 주제 파일을 새로 만들고 처음 화면(`README.md`)의 "문서 목록"에 한 줄 추가한다. 한 파일이 150줄을 넘으면 나눈다. 처음 화면에는 지금 할 일·요청·목록만 두고 긴 설명은 넣지 않는다.
7. **작업 노트에 답할 때** (위 "작업 노트" 과정):
   - 팀원 브랜치의 `작업_노트.md`에서 상태가 `답변 대기`인 글과, 그 커밋에서 바뀐 파일을 같이 읽는다. 지시서·기획 문서(`docs/design/`, 특히 `04_art_spec.md`의 바꾸면 안 되는 기준)와 맞는지 본다.
   - 답 초안을 **먼저 채팅으로 선우에게 보여 주고 허락을 받는다. 허락 전에는 어떤 브랜치에도 커밋·푸시하지 않는다.** 선우가 고쳐 달라면 고친 초안을 다시 보여 준다.
   - 허락받으면 그 글 아래 `> Claude 답변:`에 답을 쓰고(`[변경]`이면 첫 줄에 `괜찮음` / `조건부로 괜찮음: …` / `되돌리기: …`), `- 상태:`를 `답변함`으로 바꿔 **그 팀원 이름 브랜치**에 커밋·푸시한다. 커밋 설명은 `docs: <이름> 작업 노트 답변 (MM/DD 제목)`. 팀원이 쓴 다른 글이나 파일은 고치지 않는다.
   - 답 때문에 코드나 지시서를 바꿔야 하면 2번(선우 표)이나 1번(그 팀원 요청 표)에도 적는다. 이것도 선우 허락에 포함해서 묻는다.
   - 답장 끝에 "팀 단톡방에 알릴 문구"를 한 줄 붙인다(예: `유진님 작업 노트에 답 올렸어요. Pull origin 후 확인해 주세요`).
   - 작업 노트가 150줄을 넘으면 `답변함`인 오래된 글을 `작업_노트_지난것.md`로 옮긴다.
8. 이 파일들만 바꾸는 커밋은 그 작업의 PR에 같이 넣어도 되고, 따로 문서 PR로 올려도 된다. 팀원에게 바로 알려야 하면 답장에 "팀 단톡방에 알릴 문구"를 한 줄 붙인다.
