|---|---|---|

| 성재 | PC-B·장비, Blender 로봇 정리, 플레이어 색, 조종석 모델 | [성재.md](성재.md) |

## 보는 법

- 휴대폰이나 PC 브라우저에서 GitHub 레포 → `docs` → `members` → 자기 이름 파일을 누르면 됩니다.
- 맨 위 **"지금 할 일"** 과 **"다른 작업에서 온 요청"** 만 먼저 보면 됩니다. 아래는 자세한 순서입니다.
- 파일이 바뀌었는지는 맨 위 "마지막 수정" 날짜와 "바뀐 기록"으로 확인합니다.

## 각 파일의 칸

| 칸 | 내용 |
|---|---|
| 지금 할 일 | 지금부터 다음 마감까지 할 일. 관련 작업 지시서(`docs/tasks/`) 링크 |
| 다른 작업에서 온 요청 | 코드 작업(마일스톤) 중에 "이 사람이 이걸 해 줘야 한다"가 생기면 여기에 쌓임 |
| 문제·질문 보고 | 막혔을 때 어떻게 알리는지 (아래 "문제 보고하는 법") |
| AI 활용 안내 (유진·성재·윤주) | 할 일마다 AI에 맡겨도 되는 것, 직접 해야 하는 것, 요청 예시 문구 |
| 바뀐 기록 | 언제 무엇이 바뀌었는지 한 줄씩 |
| (선우만) 팀원이 보고한 문제 → 코드 담당이 할 일 | 팀원이 올린 문제·수정 요청과, 그걸 고치려고 코드 쪽에서 할 일 |

## 문제 보고하는 법

막혔거나, 이상한 점을 찾았거나, 받은 파일·지시가 틀린 것 같으면 **팀 단톡방**에 아래처럼 올립니다. 혼자 30분 넘게 붙잡지 않습니다.

```
[문제] 이름 / 지시서 번호(예: A-02 1단계)
무엇을 하다가: 
무슨 일이 생겼나: 
화면 캡처: (첨부)
```

그다음은 코드 담당(선우)이 총괄 채팅(Claude)에 이 글을 넘기고, Claude가 이렇게 정리합니다.

1. [선우.md](선우.md)의 "팀원이 보고한 문제 → 코드 담당이 할 일"에 한 줄 추가 (날짜, 보고한 사람, 내용, 코드 쪽에서 할 일).
2. 고치는 과정에서 그 팀원(또는 다른 팀원)이 다시 해야 할 일이 생기면, 그 사람 파일의 "다른 작업에서 온 요청"에 한 줄 추가.
3. 고쳐지면 두 줄 모두 상태를 "끝남"으로 바꾸고, 팀 단톡방에 "고쳤어요, 내 파일 확인해 주세요"라고 알립니다.

GitHub에 익숙하면 자기 파일에서 연필(✏️) 버튼을 눌러 직접 적어도 됩니다. 그래도 팀 단톡방에는 한 줄 알려 주세요.

## Claude 세션이 지킬 규칙

이 프로젝트의 모든 Claude 세션(총괄 채팅, 마일스톤 작업 스레드, Claude Code)은 아래를 따른다.

1. **팀원에게 원하는 것이 생기면** (마일스톤 작업 중 아트·장비·소리·외골격 쪽 요청, 지시서 변경) 그 팀원 파일의 "다른 작업에서 온 요청" 표 **맨 위**에 한 줄을 넣는다.
   - 형식: `| 날짜(MM/DD) | 어디서(작업 이름, 예: M1-05 명중 판정) | 요청(처음 하는 사람도 알 수 있게 무엇을·왜·어디에 넘기는지) | 새 요청 |`
   - 지시서(`docs/tasks/`)를 바꿔야 하는 요청이면 그 지시서도 같이 고치고 링크를 건다.
   - 그 파일의 "지금 할 일"에 영향이 있으면 같이 고친다.
2. **팀원이 문제를 보고하면** 선우.md의 "팀원이 보고한 문제" 표 맨 위에 넣고, 코드 쪽 할 일을 적는다. 고친 결과 팀원에게 다시 부탁할 일이 생기면 1번대로 그 팀원 파일에도 넣는다.
3. 고친 파일의 "마지막 수정" 날짜를 바꾸고 "바뀐 기록"에 한 줄(날짜: 무엇을, 왜) 추가한다.
4. 상태 값은 `새 요청` / `하는 중` / `끝남` 세 가지. 끝난 줄은 지우지 않는다.
5. 쉬운 한국어로 쓴다. 결정이 필요한 것은 "팀 회의에서 정할 것", 질문·파일 전달은 "팀 단톡방"으로 쓴다.
6. 이 파일들만 바꾸는 커밋은 그 작업의 PR에 같이 넣어도 되고, 따로 문서 PR로 올려도 된다. 팀원에게 바로 알려야 하면 답장에 "팀 단톡방에 알릴 문구"를 한 줄 붙인다.
