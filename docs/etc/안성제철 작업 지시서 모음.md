**결과물 넘기는 법** (둘 중 편한 쪽)

1. 레포를 clone해서 Unity로 열 수 있으면: 지시서에 적힌 폴더에 넣고, Claude Code(데스크톱 앱 Code 탭)에 "커밋하고 PR 만들어줘".

**꼭 지킬 것**

- `Scenes/Main.unity`는 **선우만** 수정합니다. 씬 작업은 `Scenes/Sandbox/Sandbox_<이름>.unity`에서 하고 프리팹으로 넘깁니다.
- 밖에서 받은 모델·텍스처·소리는 **출처를 반드시 기록**합니다(파일 이름 / 사이트 / 제목 / 만든 사람 / 라이선스 / 주소). 전시 작품이라 출처를 모르는 파일은 쓰지 않습니다.
- 모델 뼈대(뼈 이름·개수), 팔 길이 비율, 단위(m)·정면(+Z)은 바꾸지 않습니다. 바꿀면 코드가 깨집니다.
- 파일 하나 50MB 이하. 중간 저장본은 드라이브로, 확인된 버전만 레포로.
- 막히면 고치려고 애쓰지 말고 화면을 찍어 보내세요. 대부분 금방 해결됩니다.

**마감 구조**: 팀원 결과물은 마감 하루 전까지 들어와야 코드에 합칠 시간이 생깁니다(예: 중간발표용은 10/28). 11/19 기능 동결, 11/26 아트 동결, 12/7 코드 동결. 지시서 원문은 레포 `docs/tasks/`, 담당자 표는 `docs/tasks/README.md`.

## 조작감 컨셉: 이동·공격과 소리

한 줄로 정리하면 **수천 톤짜리 유압 기계를 내 몸으로 모는 느낌**입니다. 팔은 내 손을 바로 따라오지만(늦으면 멀미), 무게감은 소리·진동·외골격이 만듭니다. 코드는 이 표대로 소리·진동을 붙이고, 윤주의 소리 목록도 이 표에서 나왔습니다.

**소리 원칙 세 가지**

1. **모든 동작은 3층**: ① 기계음(로봇 몸 안의 유압 치익·서보 위잉·피스톤 철컥) → ② 충격음(쾅·텅·쿽) → ③ 꼬리(울림·파편·바람).
2. **들리는 자리**: 내 로봇 소리는 조종석 안에서 몸으로 울리듯(낮고 둔탁하고 가까이), 보스 소리는 40m 밖에서(공간감 있게, 크고 묵직하게).
3. **같은 순간에 세 가지**: 소리 + 컨트롤러 진동 + 외골격 저항이 동시에. 맞았는지는 눈을 안 봐도 소리로 알 수 있어야 합니다(헛치면 바람만, 맞으면 쾅).

**공격: 잽은 피스톤, 훅은 쇳덩이, 부스트는 로켓**

| 조종사가 하는 것 | 로봇이 하는 것 | 소리 (순서대로) | 진동·외골격 |
| --- | --- | --- | --- |
| 그립을 쥐다 | 주먹이 잠김, 공격 준비 | 철컥(기계 잠금) | 아주 짧은 진동 |
| 그립을 놓는다 | 주먹이 풀림 | 치익(공기 빠짐) | – |
| 직선으로 뻗는다(잽) | 팔이 피스톤처럼 쏘아짐 | 피슝(발사) → 쾅(짧고 단단한 명중) | 명중 순간 짧은 진동 + 외골격 0.12초 |
| 바깥에서 안으로 휘두른다(훅) | 쇳덩이를 크게 휘두름 | 후우웅(낮은 바람 + 관절 기어) → 콰직(금속 찌그러짐 + 파편) | 더 길고 강한 진동 |
| 헛친다 | 팔만 지나감 | 바람 소리만, 명중음 없음 | 없음 |
| 연계가 이어진다(2타·3타) | – | 명중음 위에 짧은 상승 신호 "딩↗", 단계마다 높게 | – |
| (훅 명중 직후 0.45초) | 슬로 연출, 부스트 가능 | 짧게 차오르는 "위잉!" | – |
| 트리거(부스트) | 팔꿈치 로켓 점화 | 쿠와앙(분사) → 폭발성 명중 + 저음 붐 | 가장 강한 진동, 외골격 해제 |
| 가드 자세로 막는다 | 강판으로 받아냄 | 텅(둔탁한 충격) + 끼이익(팔이 버티는 서보) | 강한 진동 + 외골격 0.3초 |
| 못 막고 맞는다 | 조종석이 흔들림 | 쿽(조종석 안 충격) + 짧은 경보 | 강한 진동 |

**이동: 한 걸음이 지진, 회피는 분사**

이동은 두 사람의 보조 스틱이 같은 방향일 때만 일어납니다(협동). 자유 이동은 없고 정해진 짧은 동작만 있습니다.

| 조종사가 하는 것 | 로봇이 하는 것 | 소리 (순서대로) | 진동 |
| --- | --- | --- | --- |
| 둘이 같은 방향으로 민다 | 이동 승인 | "샑샑" 두 번(호흡이 맞았다는 신호) | 짧게 |
| 앞(접근) | 근접 거리까지 2\~3걸음 | 걸음마다 치익(다리 유압) → 쿼웅(발) | 걸음마다 |
| 뒤(후퇴) | 사거리 밖으로 1\~2걸음 | 같은 소리 | 걸음마다 |
| 왼쪽·오른쪽(회피) | 다리 분사로 옆으로 미끄러짐(약 0.4초) | 피슝!(분사) → 드르륵(바닥 끌림) → 쿽(착지) | 착지 때 |
| (자동) 보스 쪽으로 몸 회전 | 허리가 천천히 도는 | 낮은 기어 "끼기기긱" | – |
| (가만히 있을 때) | 대기 | 조종석 안 낮은 기계 웅웅거림(엔진·냉각팬) | – |

두 사람의 스틱이 어긋나면 아무 일도 일어나지 않습니다. "샑샑" 신호가 안 나면 방향이 안 맞은 것이라는 걸 바로 알 수 있습니다.

### A-01 로봇 애니메이션 (Mixamo) — 1차 10/29, 2차 11/12

우리 로봇은 Mixamo 뼈대라 모델링 지식 없이 클립을 받아 그대로 씁니다. 이미 있는 것(대기·오른손 펀치·경직·연타·쓰러짐·걷기·회전)은 다시 받지 않습니다.

| 차수 | 받을 클립 | 파일 이름 예 |
| --- | --- | --- |
| 1차 (10/29) | 왼손 펀치, 크게 밀려남 | `Boss_PunchLeft.fbx`, `Boss_Knockback.fbx` |
| 2차 (11/12) | 두 손 내려찍기, 돌진, 무릎 꿇기, 뒤로 걷기, 플레이어 옆걸음 좌/우 | `Boss_SlamBoth`, `Boss_Charge`, `Boss_Kneel`, `Boss_WalkBack`, `Pilot_StrafeLeft/Right` |

1. mixamo.com에 Adobe 계정으로 로그인. 캐릭터는 기본 그대로.
2. 검색어로 찾기(punch, hit reaction, ground slam, charge, kneel, walking backward, strafe). **거대 로봇이 하기에 묵직하고 읽기 쉬운 동작**을 고른다. 후보가 여러 개면 2\~3개.
3. Download 설정: **FBX for Unity, Without Skin, 30fps**, 이동하는 클립은 **In Place** 체크.
4. 이름을 위 규칙으로 바꿔 PR로 올리거나 선우에게 전달.
5. 기존 레포의 `GroundCast.fbx`가 내려찍기로 쓸 만한지 의견을 적는다.

하지 말 것: With Skin으로 받기(파일이 20MB대로 커짐), 손가락 애니메이션. 왼손 버전이 없으면 오른손만 받아도 됨(좌우 반전은 코드 쪽에서).

1. **구매 목록**(가격·링크, 구매 전 선우 확인): USB-C 3.x Link 케이블 약 5m × 3, 랜선 2 + 스위칭 허브, 예비 Wi-Fi 6 공유기, 멀티탭·벨크로.

3. **헤드셋 확인**: 고개를 돌리면 시야가 따라옴, 양손 큐브가 컨트롤러를 따라옴, 끊김 없음.

### A-02 로봇 메시 정리 (Blender) — 11/05

현재 모델은 렌더러 291개·재질 124개라 무겁고, 텍스처를 빼면 비누처럼 둥글게 보입니다. 목표는 **렌더러 8개 이하, 재질 6개, 각진 모서리**입니다.

1. 레포의 `Assets/_Anseong/Art/Robot/Source/BossUpdatedCompatible.fbx`를 Blender로 임포트(텍스처 폴더도 함께). 새 `.blend`로 저장.
2. **병합**: 메시를 Join(Ctrl+J). 크면 몸통·팔·다리로 나눠 최대 8개. 뼈 가중치 유지 확인.
3. **각진 모서리**: Shade Auto Smooth 30\~45°, 필요한 곳 Mark Sharp.
4. (마지막 수단) 울퉁불퉁한 곳만 Decimate(Planar). 포즈 모드에서 굽혀 찢어짐 확인.
5. **원래 재질이 붙어 있을 때** 두 번째 UV를 만들고 굽기: AO 2048 → `Robot_v026_AO.png`, Tripo 색 아틀라스 4096 → `Robot_v026_Atlas.png`.
6. **재질 6개로 다시 배정**: ArmorMain(큰 장갑), ArmorAccent(포인트), Metal(관절), Dark(안쪽·틈), Glow(눈·라인), Trim(테두리). 애매하면 Dark.
7. **내보내기**: Armature + Mesh만, **단위 m, Armature 스케일 1, 정면 +Z·위 +Y**. `Robot_v026_clean.fbx`. 확인된 버전만 레포에(내보낼 때마다 약 20MB씩 쌓임).

주의: 단위 cm·스케일 100으로 나가면 Unity에서 몸이 사라집니다(M0-03에서 확인). 뼈 이름·개수·팔 비율은 바꾸지 않습니다. Blender에서 막히면 유진이 돕고, 그래도 안 되면 Claude가 Unity 도구로 대신합니다.

## 고건 — 외골격 전담

한 팔용 외골격이 **PC에서 보낸 명령대로 저항을 주고, 명령이 끊기면 스스로 풀리게** 만듭니다. 펌웨어 코드는 Claude가 쓰고 고건이 올려서 시험합니다. 외골격이 없어도 게임은 끝까지 돌아야 하므로 **안전이 가장 우선**입니다.

### H-01 외골격 한 팔 시제품 — 10/29 (중간발표에서 시연)

| 사건 | 명령 예 | 느낌 |
| --- | --- | --- |
| 명중 | `R,180,120` | 짧은 저항 0.12초 |
| 가드 접촉 | `R,255,300` | 강한 저항 0.3초 |
| 부스트 | `R,0,0` | 저항 해제 |

명령 형식: 115200bps, 한 줄 `R,<세기 0-255>,<시간ms>`. 명령이 0.2초 동안 없으면 저항 0(워치독).

0. **현재 상태를 먼저 적는다**: 모터·드라이버·전원, ESP32 보드, 어디까지 조립됐는지, 사진 1장. 이걸 보고 Claude가 펌웨어를 맞춤.
1. **안전장치(필수)**: 손으로 바로 누르는 비상 정지 스위치, 전류 제한, 힘주면 기계적으로 풀리는 구조. 모터가 팔을 끌어당기는 방향으로는 힘이 걸리지 않게.
2. Claude Code에 "H-01 읽고 내 하드웨어에 맞춰 ESP32 펌웨어 써줘" → `Hardware/Exo/firmware/`.
3. Arduino IDE 시리얼 모니터(115200, LF)에서 위 명령을 직접 입력해 시험. 명령을 안 보내면 0.2초 안에 풀리는지, 비상 정지·기계적 풀림이 되는지.
4. 팔에 차고 10분 이상 써 보고 불편한 점·열·소음을 적는다.
5. 중간발표용 30초 영상 → 유진에게.
6. 두 번째 팔 부품 목록·가격.

하지 말 것: 안전장치 없이 사람 팔에 차기, 팔을 실제로 끌어당기는 동작.
