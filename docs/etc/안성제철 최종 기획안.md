Oct 16, 2026 · @sunwooPark

## 한 판의 흐름

한 판은 5분 이상, 최대 10분 내외이고, 보스 HP 구간으로 페이즈가 바뀌며 앞에서 배운 기술은 끝까지 그대로 씁니다(누적형).

1. **착용 전 안내 (운영자, 30초)**: 담당 팔, 그립=공격 유지, 트리거=부스트, 반대 손 스틱=이동.
2. **기체 점검 (약 60\~90초)**: 사령관 음성 + 손 근처 표시로 한 번에 하나씩.
   1. 담당 팔 들기 → 화면 로봇 팔 연결 확인
   2. 편한 가드 자세에서 그립 → 가드 기준 저장
   3. 정면으로 끝까지 뻗고 그립 → 도달 거리 저장
   4. 그립 유지하고 훈련 표적 치기 → "버튼 + 실제 명중" 학습
   5. 양팔 가드 → 두 사람 모두 준비 완료
3. **출격 (자동 연출, 약 10초)**: 정비고 문이 열리고 로봇이 걸어 나감. 조작 없음.
4. **보스전 3페이즈 (약 4\~7분)**: 아래 표.
5. **합동 필살기 (약 15초)**: 보스 HP 10%에서 보스가 무릎 꿇고, 두 사람이 담당 팔을 정면으로 뻗어 컨트롤러의 모든 버튼을 누른 채 유지하면 1.5초 충전 후 가슴 광선 3초.
6. **결과 (약 15초)**: 클리어 시간·성공 연계 수 표시 → 운영자가 재시작.

| 페이즈 | 보스 HP | 새로 등장하는 보스 기술 | 조종사가 익히는 것 |
| --- | --- | --- | --- |
| 1 | 100 → 60% | 좌/우 단발 펀치(일반) | 해당 팔 가드, 빈틈에 잽–잽–훅, 명중 후 부스트 |
| 2 | 60 → 25% | + 두 손 내려찍기(강), 좌우 연타 | 양팔 가드, 연타를 번갈아 막기 |
| 3 | 25 → 10% | + 가드 불가 돌진 | 같은 방향 협동 회피, 회피 성공 후 긴 반격 기회 |

**패배 처리(제안)**: 로봇 HP가 0이 되면 "기체 재기동" 연출 후 해당 페이즈 처음부터 한 번 재시작합니다. 두 번째 패배면 결과 화면으로 넘어갑니다. 관객이 대부분 완주하도록 보스 피해량을 낮게 잡습니다.

## 전투 규칙과 초기 수치

규칙은 ChatGPT 기획서의 확정 내용을 그대로 쓰고, 수치는 기존 통합 씬에서 쓰던 값을 출발점으로 삼습니다. 모든 수치는 Inspector에서 바꿀 수 있게 만들고, 실기 테스트 CSV로 조정합니다.

| 규칙 | 내용 | 초기값(제안) |
| --- | --- | --- |
| 공격 인정 | 그립 유지 + 실제 궤적 + 실제 주먹 접촉. 그립 없으면 팔은 움직이되 피해 0 | – |
| 잽 판정 | 직선으로 뻗음 | 좌우폭/전진 ≤ 0.55, 직진도 ≥ 0.86 |
| 훅 판정 | 바깥에서 안쪽으로 휘두름 | 바깥 준비 ≥ 10cm, 안쪽 스윕 ≥ 22cm |
| 재장전 | 한 번 친 뒤 손이 중립 근처로 돌아와야 다음 공격 | 반경 12cm, 0.15초 유지 |
| 연계 | 잽(A) → 잽(B) → 훅(A). A는 어느 쪽이든 가능, 안내는 오른손 시작 | 다음 명중까지 2.4초 |
| 연계 종료 | 헛침, 차례 아닌 사람의 공격, 시간 초과, 직접 피해 | – |
| 부스트 | 마지막 훅 **명중 후** 그립 유지 + 트리거. 실패해도 훅 피해 유지 | 입력창 0.45초, 슬로우 0.3초(속도 0.35) |
| 피해(보스 HP 대비) | 잽 / 훅 / 부스트 추가 | 3% / 5% / +6% |
| 일반 공격 | 들어오는 쪽 담당 팔 가드 → 피해 0 | 예고 1.2초 |
| 강공격 | 양팔 가드. 한 팔만이면 피해 감소 없는 실패 | 예고 1.8초 |
| 가드 불가 | 같은 좌우 방향 협동 회피. 미리 옆에 서 있는 건 불인정 | 예고 2.0초, 명중 0.6초 전부터 입력 인정 |
| 가드 판정 | 주먹이 "가드 영역"(보정한 가드 위치 ±25cm, 얼굴 앞) 안 + 전완이 세워짐 | 전완 수직에서 40° 이내 |
| 반격 기회 | 보스 공격이 끝난 뒤 빈틈 | 기본 1.5초, 가드·회피 성공 시 3.0초 |
| 협동 이동 | 두 사람 보조 스틱이 같은 방향일 때만 | 크기 ≥ 0.5, 방향 차이 25° 이내 |
| 전투 이동 | 앞 = 근접 거리까지 접근, 뒤 = 사거리 밖 후퇴, 좌/우 = 회피 이동 | 정해진 모션, 자유 이동 없음 |

가드 판정은 기존 코드("보정 가드보다 15cm 위")를 버리고 위치 영역과 전완 각도로 새로 만듭니다. 화면 자세와 판정은 분리해서 따로 확인합니다.

## 시점과 65m 스케일

제안: 조종사는 사람 크기 그대로 **로봇 머리 높이의 조종석**에 서고, 바깥을 직접 봅니다. 로봇 팔만 배율로 움직입니다. 렌더텍스처 중계 화면은 쓰지 않습니다.

- **월드는 실제 크기로 만듭니다.** v026 모델은 임포트하면 약 1m 높이라서 약 65배로 키웁니다(임포트 후 실측해서 맞춤). 보스도 같은 크기입니다.
- **조종사 카메라(XR Origin)는 확대하지 않습니다.** 사람 눈 간격과 머리 움직임이 그대로라서, 60m 넘는 높이에서 내려다보는 거대감이 자연스럽게 생깁니다.
- **팔 매핑은 어깨 기준 각도를 보존합니다.** 로봇 주먹 목표 = 로봇 어깨 + (사람 손 − 보정한 사람 어깨) × (로봇 팔 길이 ÷ 개인 팔 길이). 눈이 어깨 근처에 있으므로, 내가 본 방향으로 손을 뻗으면 로봇 주먹도 같은 방향으로 갑니다. 배율은 약 35\~40배가 됩니다.
- **머리 높이를 고른 이유는 시야 가림(D05)입니다.** 사람이 복싱 가드를 하면 주먹이 턱 높이라 그 위로 앞이 보입니다. 조종석이 가슴에 있으면 로봇의 가드 주먹이 눈보다 위에 와서 보스를 가립니다.
- **조종석은 실제 형상으로 만듭니다.** 바닥, 양옆 콘솔, 앞쪽 창틀 정도. 두 사람 사이 간격은 실제 바닥 테이프 간격과 같게 둡니다.
- **멀미 방지**: 로봇 몸은 보스가 정면에서 ±20° 넘게 벗어날 때만 초당 30° 이하로 천천히 돌립니다. 회피·접근은 0.4초 안팎의 짧은 이동에 시야 비네팅을 씁니다. 로봇이 묵직한 건 팔 반응으로 표현하고, 조종사 카메라는 절대 늦추지 않습니다.
- **거대감 단서**: 제철소의 긴 직선 마당. 가운데 폭 약 100m는 비워서 로봇과 보스 사이에 장애물이 없고 좌우 회피가 되게 합니다. 발밑에는 차량·컨테이너, 양옆 가장자리에는 팔 높이(25\~45m)의 사일로·크레인, 바깥에는 눈높이 이상(60\~120m)의 고로·굴뚝. 양옆 구조물 중 2\~3개는 훅·회피에 걸리거나 밀려난 보스가 부딪히면 부서집니다(M5, 미리 쪼개 둔 조각으로 바꿔치기). 구조물에 닿는 건 공격으로 치지 않습니다.

M0 주에 이 구성을 헤드셋으로 먼저 확인합니다. 머리 높이가 어색하면 가슴 상단으로 내리고 가드 매핑을 아래로 조정하는 것이 대안입니다.

**플레이어 로봇은 "팔만 조종"이지 "팔만 있는" 것이 아닙니다(10/16 검토).** 로봇 몸 전체가 있고, 조종사가 직접 움직이는 것만 두 팔입니다. 조종석이 머리 높이라 눈에 보이는 건 주로 두 팔과 아래쪽 가슴·다리이므로 실현 가능합니다.

- 두 팔: 조종사 손 → IK (왼팔 PC-A, 오른팔 PC-B). 손가락은 주먹 고정
- 몸통·다리: 대기 클립을 재생하고 그 위에 팔 IK를 덮어씀. 접근·후퇴·회피는 코드 이동 + 걷기·옆걸음 클립(보스와 같은 뼈라 클립 공유, 새로 필요한 건 옆걸음 좌/우뿐)
- 몸 회전: 보스 쪽으로 코드가 천천히 돌림
- 머리: 숨김. 두 조종사 모두 머리 안 조종석에 있으므로 어느 PC에서도 보이지 않음
- 관객 화면: 각 PC 모니터에 조종사 1인칭 화면만 띄움(헤드셋 미러, 추가 비용 없음). 3인칭 카메라가 없으므로 몸 전체가 보일 일이 없음. 고개 흔들림으로 관객이 어지러워하면 M5에서 모니터만 부드럽게 따라가는 방식 검토

## 기술 구조

기존 코드는 서버가 두 사람의 팔까지 계산했지만, 새 구조에서는 각 PC가 자기 조종사의 팔을 즉시 그리고 명중 판정도 자기 쪽에서 합니다. 서버(PC-A)는 보스와 전투 규칙만 맡습니다.

&#91;embedded content: PC 2대 구성 · 각 PC에 퀘스트 1대와 외골격 1개\]

- **팔 자세**: 각 PC가 자기 조종사의 머리·양손 자세를 비신뢰(Unreliable)로 60Hz 전송. 받는 쪽은 100ms 버퍼로 보간해서 그립니다. 자기 팔은 절대 네트워크를 거치지 않습니다.
- **명중 보고**: 때린 쪽 PC가 궁적 분류 + 주먹 접촉을 확인하고 `명중(팔, 종류, 시각, 타격 ID)`을 신뢰(Reliable) RPC로 서버에 보냅니다. 서버는 연계 차례·반격 기회·중복만 검사하고 결과를 양쪽에 알립니다.
- **가드**: 각 PC가 자기 팔의 가드 여부를 매 틱 올리고, 서버는 보스 공격 명중 순간의 값으로 판정합니다.
- **보스**: 서버가 상태(공격 종류 + 시작 틱)를 NetworkVariable로 복제하고, 클라이언트는 같은 시점부터 애니메이션을 재생합니다.
- **외골격**: 각 PC가 자기 ESP32만 제어합니다. 명령은 `R,<세기 0~255>,<시간ms>` 한 줄(115200bps). 펌웨어는 200ms 동안 명령이 없으면 0으로, 전류 제한과 기계적으로 풀리는 장치를 반드시 둡니다. 명중=짧은 저항, 가드 접촉=강한 저항, 부스트=저항 해제.
- **1인 양팔 모드**: 같은 코드를 한 PC가 호스트로 돌리며 두 팔을 모두 로컬로 맡습니다. 보조 입력은 두 스틱을 한 사람이 누릅니다.
- **NGO 설정**: Unity Transport 직결(서비스 없음), 틱 60, 포트 7777. 접속은 2명까지만 승인하고 호스트 = 왼쪽 조종사입니다.

## Unity 프로젝트 사양

Unity 프로젝트는 하나만 두고, 패키지는 꼭 필요한 6개만 설치합니다. 기존 프로젝트가 두 개로 갈라지고 템플릿·SDK가 쌓인 것이 혼란의 큰 원인이었습니다.

| 항목 | 정한 것 |
| --- | --- |
| Unity | **6000.3.26f1** (성재님이 이미 쓰던 버전). 다섯 명 모두 같은 버전 |
| 템플릿 | Universal 3D (URP) |
| 패키지 | OpenXR Plugin, XR Interaction Toolkit(XR Origin·입력 액션만 사용), Input System, Netcode for GameObjects, Test Framework, URP(템플릿 포함) |
| 설치 안 함 | Meta XR SDK, Movement SDK, Unity Gaming Services·Relay·Vivox, VR Multiplayer 템플릿, Animation Rigging(IK는 직접 계산) |
| XR 설정 | PC(Windows) 탭에서 OpenXR 켜기. 컨트롤러 프로필: Meta Quest Touch Plus + Oculus Touch. Quest Link 앱을 OpenXR 런타임으로 지정 |
| Player 설정 | Api Compatibility Level = **.NET Framework** (ESP32 시리얼에 `System.IO.Ports` 필요) |
| 직렬화 | Force Text, Visible Meta Files |
| Git | LFS 없이 일반 Git. 파일 하나 50MB 이하. 베이크된 대용량 .anim 금지 |

폴더 구조(제안):

```
Assets/_Anseong/
  Runtime/Core       ← 수학·유틸 (MechaArmStability 등)
  Runtime/Pilot      ← 입력·보정·팔 IK·주먹 포즈
  Runtime/Combat     ← 펀치 인식·연계 규칙·가드·접촉
  Runtime/Boss       ← 보스 상태기계·패턴
  Runtime/Net        ← 접속·동기화
  Runtime/Haptics    ← 컨트롤러 진동·ESP32 시리얼
  Runtime/Flow       ← 기체 점검·페이즈·결과·재시작
  Runtime/UI         ← HUD
  Editor/
  Tests/EditMode/    ← 규칙·수학 테스트
  Art/{Robot,Cockpit,Pilot,Environment,Weapons}
  Audio/
  Scenes/Main.unity
  Scenes/Sandbox/    ← 팀원별 Sandbox_<이름>.unity
```

작업 규칙:

- **씬 소유권**: `Main.unity`는 선우님만 수정합니다. 다른 사람은 자기 Sandbox 씬에서 만들고 프리팹으로 넘깁니다. 씬 병합 충돌을 원천 차단합니다.
- **브랜치**: `main` 보호, 사람별 `feat/<이름>-<기능>` 브랜치, PR로 병합.
- **asmdef**: `Anseong.Runtime`, `Anseong.Editor`, `Anseong.Tests.EditMode` 세 개. 검증·디버그 코드가 빌드에 섞이지 않게 합니다.
- **Claude Code 규칙**: `.unity`·`.prefab`·`.meta` 직접 수정 금지, `[InitializeOnLoad]`·`RuntimeInitializeOnLoadMethod` 금지, 기능 하나씩 plan mode로 계획 후 구현.
