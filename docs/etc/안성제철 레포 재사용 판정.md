## 결론

새 프로젝트로 파일째 옮길 것은 순수 로직 파일 10여 개와 무기·팔·파일럿 에셋뿐이고, 나머지는 로직만 참고해 다시 쓰는 게 빠릅니다. 직접 작성 스크립트 약 1만 9천 줄 중 절반 이상이 AI 에이전트가 만든 검증·씬 생성 도구라 가져갈 필요가 없습니다.

- **그대로 가져갈 것:** 팔꿈치 안정화 수학, 유진님 보스 이동·회전·헤비펀치, 보스 공격 데이터 구조, HUD 와이어프레임 3종, LAN 규칙 유틸, 파일럿 머리 숨김.
- **로직만 살릴 것:** 잽/훅 궤적 분류, 콤보·부스트·가드 규칙, 개인 팔 길이 보정, 팔 IK(로컬 PC의 `ControllerArmFollower.Practice.cs`가 최신·최선), 보스 공격 상태기계, 보스 접촉 정지.
- **버릴 것:** 네트워크 세션 클래스(구조가 새 계획과 반대), 검증·빌더 Editor 스크립트 전부, VR Multiplayer 템플릿(`VRMPAssets`), 1인 연습 모드, Meta SDK·Movement 샘플.
- **가장 큰 문제는 보스 모델입니다.** Unity 안의 보스는 플레이어 메카(v026)를 변환한 임시본이고 크기도 약 2.7m입니다. 실제 보스 최신본 BossV11은 리그가 없고 116만 폴리곤이라 새로 리깅·감량해야 합니다.

검토 기준은 GitHub develop(10/15 c060172)과 사용자 PC의 `_Project` 폴더입니다. Unity를 실행해 확인한 것은 없고, 모두 코드와 파일을 정적으로 읽은 결과입니다.

## 옮기면서 반드시 고칠 버그

로직을 참고할 때 같은 실수를 다시 만들지 않도록, 원본에서 확인한 문제입니다. 1·2·3·5번은 직접 코드를 열어 확인했습니다.

1. **자기 팔을 서버 echo로 그림** (`RobotPlaySession.cs:313-314`). 자기 팔은 반드시 로컬 입력으로 즉시 그립니다.
2. **팔 포즈를 50Hz Reliable RPC로 전송** (`RobotPlaySession.cs:266`). 하나가 늦으면 뒤가 다 밀립니다. Unreliable 전송으로.
3. **빠른 펀치 샘플을 서버가 버림** (`RobotPlaySession.cs:282-283`). 직전 값보다 많이 움직이면 버려서, 펀치 최고속 구간을 인식기가 놓칩니다.
4. **LAN에서 손 회전과 개인 보정이 꺼짐** (`RobotPilotInput.cs:87`, `RobotPlaySession.cs:391, 409`).
5. **보스 일반 공격이 항상 오른팔 가드 요구** (`IntegratedBossEncounter.cs:59`). 회피 판정은 로봇 x좌표 |x| ≥ 0.5만 봄(54).
6. **가드 판정이 "보정한 가드 자세보다 15cm 더 위"** (`RobotCombat.cs:111`). 앞뒤 위치와 전완 방향을 안 봄.
7. **이동 스틱이 펀치하는 손** (`RobotPilotInput.cs:201`). 기획은 반대 손.
8. **콤보가 0.25초 입력 끊김에도 초기화** (`RobotPlaySession.cs:296-297`).
9. **팔 IK roll 누적 드리프트** (`ControllerArmFollower.cs:123-124`). Practice solver의 절대 재구성 방식으로 해결.
10. **보스 Stun·Dead가 Idle만 재생** (`BossAnimationDriver.cs:123`). Stagger·Death 클립이 있는데 안 씀. 컨트롤러는 전이 0개라 전부 코드 CrossFade.
11. **코어 노출이 실제로 발동하지 않음**: 공격 데이터 14개 모두 `coreExposureSeconds: 0`.
12. **콕핏 바깥 화면 끊김 유력 원인**: 밉맵 없는 2048² 렌더텍스처 3장을 작게 축소해 그림(반짝임), 외부 카메라 3대 추가 렌더로 GPU 과부하 → Link 재투영. 새 설계에서는 렌더텍스처 중계를 쓰지 않는 쪽을 권장.
13. **검증 코드가 빌드에 포함**: `RuntimeInitializeOnLoadMethod` smoke runner, 런타임 `UnityEditor.SessionState`, asmdef 없음.

순서와 일정은 별도 문서 「안성제철 최종 기획안」에 정리합니다. 이식의 원칙만 적습니다.

1. 순수 로직(KEEP 표의 수학·규칙 파일)을 먼저 옮기고 EditMode 테스트로 감쌉니다.
2. 모델은 소스 FBX만 새로 임포트하고, 기존 씬·프리팹·.anim·Editor 빌더는 가져오지 않습니다.
3. ADAPT 항목은 "원본 파일:줄을 참고해 새 구조로 다시 작성"하도록 Claude Code에 지시합니다. 원본 파일을 통째로 붙여넣지 않습니다.
4. 기존 레포는 읽기 전용 참고 자료로 남깁니다.
