# Claude Code 사용 가이드

Oct 16, 2026 · @sunwooPark

PowerShell 없이 Claude 데스크톱 앱의 **Code 탭**에서 말로 시키면 됩니다. 파일 수정, git 커밋·푸시·PR까지 Claude가 직접 하고, 선우님은 계획을 승인하고 헤드셋으로 확인만 하면 됩니다.

## 처음 한 번 할 준비

Claude 데스크톱 앱에 Claude Code가 이미 들어 있어서 따로 설치할 것은 Git 하나뿐입니다. Code 탭은 Pro 이상 요금제에서 쓸 수 있습니다.

1. **Git for Windows 설치**: [git-scm.com/downloads/win](https://git-scm.com/downloads/win)에서 받아 기본 설정 그대로 설치합니다. Claude가 커밋·푸시하고 명령을 실행할 때 씁니다.
2. **Code 탭 열기**: 데스크톱 앱 위쪽 가운데의 **Code** 탭을 누릅니다. (Chat 탭은 파일 접근이 없는 일반 대화, 지금 이 총괄 채팅이 있는 곳입니다.)
3. **폴더 고르기**: 환경은 **Local**을 고르고 **Select folder**로 프로젝트 폴더(`Desktop\re-capstone\anseong-steel-v2`)를 선택합니다.
4. **첫 PR 때 한 번**: PR을 만들 때 GitHub CLI 설치를 물어보면 설치하고 GitHub 계정으로 로그인합니다.

참고로 최종 기획안의 "지금 바로 할 일" 1·5단계(백업 브랜치, git init·첫 푸시)도 PowerShell 대신 Code 탭에서 Claude에게 시켜도 됩니다. Unity Hub에서 프로젝트를 만드는 3단계와 XR 설정 4단계만 직접 하면 됩니다.

## 권한 모드

보내기 버튼 옆 선택칸에서 Claude가 얼마나 혼자 해도 되는지 고릅니다. **처음에는 Plan으로 계획을 받고, 승인 후 Accept edits로 바꿔 구현**하는 순서를 권합니다.

| 모드 | Claude가 하는 것 | 언제 |
| --- | --- | --- |
| **Plan** | 파일을 읽고 계획만 제안. 아무것도 수정하지 않음 | 작업 시작할 때 항상 |
| **Accept edits** | 파일 수정은 바로 적용, 명령 실행은 물어봄 | 계획 승인 후 구현할 때 (추천) |
| **Manual** | 파일 수정과 명령 실행을 하나하나 물어봄 | 처음 며칠 익숙해질 때, 중요한 파일 건드릴 때 |
| **Auto** | 위험한 동작만 자동으로 막고 나머지는 알아서 | 익숙해진 뒤 단순 반복 작업 |

수정이 생기면 `+12 -1` 같은 표시가 뜹니다. 누르면 바뀐 내용(diff)이 파일별로 보이고, 줄을 클릭해 댓글을 달면 Claude가 그 댓글대로 다시 고칩니다. 여러 댓글은 Ctrl+Enter로 한 번에 보냅니다.

## 작업 하나를 끝내는 순서

작업 하나 = 세션 하나 = PR 하나입니다. 총괄 채팅(Chat 탭의 이 대화)에서 지시서를 받고, Code 탭에서 실행하고, 결과를 다시 총괄에 가져오는 순환입니다.

1. **총괄에서 지시서 받기**: 제가 레포에 `docs/tasks/M1-01-...md`를 올립니다.
2. **Code 탭에서 새 세션**: 왼쪽 사이드바 **+ New session**(Ctrl+N) → 폴더 확인 → 모드는 **Plan**.
3. **최신 코드 받고 계획 요청**: "git pull 하고, docs/tasks/M1-01 읽고 계획 세워줘".
4. **계획 검토**: 이상하면 그 자리에서 고쳐달라고 말합니다. 괜찮으면 모드를 **Accept edits**로 바꾸고 "계획대로 진행해".
5. **Unity는 켜둔 채로**: Claude가 스크립트를 저장하면 Unity가 자동으로 컴파일하고, Claude가 에러 로그를 읽어 스스로 고칩니다.
6. **헤드셋으로 확인**: Play를 눌러 직접 해보고, 결과를 말로 알려줍니다. 예: "잽은 되는데 훅이 잽으로 인식돼". 화면 캡처를 끌어다 놓아도 됩니다.
7. **커밋과 PR**: "지시서 결과 칸 채우고, 커밋하고 PR 만들어줘". 또는 **Create PR** 버튼.
8. **총괄에 보고**: 이 채팅에 "PR #번호 봐줘"라고 보내면 제가 코드를 리뷰하고 다음 지시서를 씁니다.

세션은 사이드바에 남아 있어서 다음 날 눌러서 이어갈 수 있습니다. 대화가 너무 길어지면 새 세션을 여는 게 낫습니다. 기억해야 할 것은 지시서와 레포 파일에 남아 있기 때문입니다.

## 새 세션마다 레포를 알려줘야 하나요?

아니요. 세 가지가 자동으로 알려줍니다.

| 무엇을 | 어떻게 알게 되나 | 선우님이 할 일 |
| --- | --- | --- |
| 작업할 폴더 | 세션을 열 때 고른 폴더 안에서만 일함. 사이드바가 프로젝트별로 세션을 묶어줌 | 새 세션에서 `anseong-steel-v2` 폴더 선택 |
| GitHub 주소 | 첫 푸시 때 `git remote add origin`으로 폴더의 git 설정에 저장됨 | 처음 한 번만 |
| 레포 구조·규칙·지시서 위치 | 레포 맨 위 `CLAUDE.md`를 세션 시작 때마다 자동으로 읽음 | 없음. 총괄 채팅에서 제가 작성·관리 |

그래서 새 세션 첫 마디는 "git pull 하고 docs/tasks/<번호> 읽고 계획 세워줘" 한 줄이면 됩니다.

## 복사해서 쓰는 요청 문장

| 상황 | 그대로 입력할 문장 |
| --- | --- |
| 작업 시작 | git pull 하고, docs/tasks/<번호> 읽고 계획 세워줘. 아직 수정하지 마. |
| 계획 승인 | 계획대로 진행해. 끝나면 Unity 컴파일 에러 없는지 Editor.log 확인해줘. |
| 테스트 결과 전달 | 헤드셋에서 해봤는데 <증상>. 원인 찾아서 고쳐줘. |
| 수치 조정 | <항목> 값을 Inspector에서 바꿀 수 있게 빼줘. |
| 마무리 | docs/tasks/<번호> 결과 칸 채우고, feat/<이름> 브랜치로 커밋하고 PR 만들어줘. |
| 상황 파악 | 지금까지 바꾼 파일과 이유를 짧게 정리해줘. |
| 되돌리기 | 방금 바꾼 거 취소하고 마지막 커밋 상태로 돌려줘. |
| 첫 세팅(1회) | 이 폴더를 git 레포로 만들고 Unity용 .gitignore 받아서 첫 커밋 후 https://github.com/Lunatic2339/anseong-steel-v2 에 푸시해줘. |

`@파일이름`을 입력하면 그 파일을 대화에 바로 붙일 수 있고, `/`를 누르면 쓸 수 있는 명령 목록이 나옵니다.

## 막혔을 때와 하지 말 것

**막혔을 때**

- **엉뚱한 방향으로 갈 때**: 정지 버튼을 누르거나, 멈추지 않고 바로 "그거 말고 \~해줘"를 입력하고 Enter.
- **같은 에러를 계속 못 고칠 때**: 세 번 넘게 반복하면 멈추고, 에러 메시지와 증상을 총괄 채팅에 가져오세요. 제가 원인을 보고 지시서를 고칩니다.
- **대화가 길어져 헷갈려할 때**: 새 세션을 열고 "docs/tasks/<번호> 읽고 이어서 해줘".

**하지 말 것**

- 같은 파일을 두 세션이나 두 사람이 동시에 고치기.
- `Main.unity` 씬이나 프리팹을 Claude에게 직접 수정시키기. 씬 연결은 Unity 에디터에서 직접 하거나, "씬을 만드는 에디터 메뉴 스크립트"를 짜달라고 합니다.
- 기능 여러 개를 한 세션에 몰아서 시키기. 지시서 하나씩.
- Unity 실행 확인을 건너뛰고 커밋하기. "테스트 통과"라는 Claude의 말보다 헤드셋에서 본 것이 기준입니다.
